## 本次维护阅读发现的R15注意事项

本次只增补维护注释，原R15文件逐字节保留：

- `minimum_custody_chain_hops`在生成器中由`len(custody_chain)`计算。这里存储的是5个节点引用，不能据此证明“最少5条推理边”，也没有证明每个节点不可删除。
- Oracle重建直接读取私有`gold_sheet`标签。它证明私有映射与金标一致，尚未独立解析公开自然语言来验证裁决。
- 四种`authority_protocol`表现为不同裁决规则；其节点列表均采用E/C/H/V/登记表的相同排列。后续应区分“规则类型多样”和严格图论意义的“拓扑不同”。
- R15公开counter extracts已提供匿名统计总量，公开输入没有完整逐球原始记录。当前主要测试身份/来源映射裁决，不能描述为已检验完整逐球重新计数能力。
- `2^34`只对应成对字段守恒组合。完整错误世界只检查了部分总量与基本可行性；不能推断所有组合满足全部FOW、Partnership与比赛时序约束。
- 成对runs/balls置换有共享实体配对，34个组件是构造中的分别裁决单元。统计独立性与实际最小决策数还需消融检验。

这些问题可由`workspace_snapshot/vett_cricket_pilot_v1/scripts/build_r15_synthetic_dualworld.py`直接核查。下一轮应先增加公开输入独立解析器与删证据反事实检查，再报告最短充分证据链。

## 失败轮的保存等级

| 等级 | 含义 |
| --- | --- |
| 完整候选文件 | 对应失败文本、金标、生成器或中间产物仍可找到；全部已归档 |
| 历史包快照 | 当前工作区已变化，旧ZIP中保有当时版本；原包字节与内部成员清单保留 |
| 仅报告/指标记录 | 原候选曾被覆盖或未落盘，现存迭代报告记载其失败；无法恢复当时完整状态 |
| 未完成/未输出 | 如R15新根求解超时，记录尝试与时间预算；没有可冒充完成品的账本 |

R15失败JSON和迭代报告保留两次求解超时、22/12位置偏置与同构链规则问题。它们不构成每次失败候选源码和文本的完整快照。R13/R14也应依照实际文件逐项判定，不能仅凭“保留失败”文字断言可逐字复现全部被覆盖状态。

## P1：下一轮完整实施顺序

1. 先对R13-C/R14/R15做公开证据独立恢复及删证据测试，收紧难度指标定义。
2. 冻结待测文本、方法提示和分母，再运行真实Direct/CoT/T3/Map&Make。开发者已读金标，不能充当严格盲测求解上下文。
3. 按身份错绑、来源权威、撤销/修订、重复计数、数值聚合、输出契约、遗漏逐类归因。
4. 每次只改变主要机制，保留paired控制样本；需要时加入oracle-authority与oracle-mapping辅助输入以定位瓶颈。
5. 固定开发轮后，在新独立根上验证；单个根上反复调难不能作为总体失败率证据。
6. 只有获得可核验逐球资料和使用许可，才扩展观测事件主轨。当前生成式文本与合成顺序独立标记。
7. 候选达到稳定、可解释难度后，优先扩样本和人工自然化。高错误率门槛同时检查是否来自无证据金标、模板指纹、不可恢复性或序列化。
