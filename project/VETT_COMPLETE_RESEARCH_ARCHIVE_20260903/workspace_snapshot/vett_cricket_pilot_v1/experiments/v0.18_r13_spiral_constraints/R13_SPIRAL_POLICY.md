# VETT Cricket 螺旋升级协议

## 1. 固定闭环

每一轮必须按以下顺序执行：

1. 冻结公开输入、方法提示、输出模式和评分口径。
2. 分别运行Direct、CoT、T3和Map&Make，预测先写入独立目录。
3. 所有预测完成后统一冻结SHA-256，再读取私有金标。
4. 将错误拆分为事实选择、作用域、修订、重复计数、跨表守恒、缺失、幻觉和序列化。
5. 只针对真实事实错误对应的机制升级数据；格式错误单列，不能用于抬高主错误率。
6. 保留失败版本、升级理由、预期攻击对象和升级后的实测变化。

## 2. 方法弊端到数据升级的映射

| 实测失败 | 允许的数据升级 | 禁止的伪难度 |
| --- | --- | --- |
| Direct依赖首条、末条或多数声明 | 打乱出现顺序、重复已撤回事实、分散来源权威 | 无意义延长文本 |
| CoT逐行求解后忽略全局状态 | 跨行共享约束、跨表守恒、局部双世界 | 纯数学谜题或任意密码 |
| T3抽取元组后丢失来源或作用域 | 共享实体、同名记录、延迟来源映射、跨批次连接 | 隐藏必要证据 |
| Map&Make单调写表或漏掉后置例外 | 批次级REVISE、撤回范围、延迟例外、非局部更新 | 仅增加同义改写 |
| 所有方法只发生格式错误 | 原子化字段、固定类型规范、格式指标独立 | 将括号、空格、JSON类型当事实错误 |
| 所有方法事实错误低于10% | 改变依赖拓扑；不增加伪事实密度 | 为追求60%不断重复错误值 |

## 3. 每轮强制门槛

- canonical root自动一致性检查通过。
- 每个金标有公开正证据；错误事实只能是来源受限的公开声明。
- Oracle事实错误率为0%。
- 公开、私有文件隔离；盲包不得包含gold、decoy、证据状态或评分信息。
- 固定候选位置策略应接近随机水平。
- 完全重复句为0；强归一化模板重复率低于25%。
- 复合字段先原子化，空金标结构位预先排除。
- 真实模型预测冻结前不得读取私有材料。

## 4. 根据真实结果选择下一步

| 四方法事实错误率 | 下一步 |
| --- | --- |
| 全部低于10% | 进入下一拓扑；增加跨行共享依赖或部分可观察守恒 |
| 至少两种处于10%–30% | 保持难度，扩到3–5个独立根并人工自然化 |
| 至少两种处于30%–60% | 冻结机制，扩到不同赛制和叙述体裁；补多模型重复实验 |
| 三种以上超过60% | 停止继续加难，优先检查自然性、唯一解、训练污染和人为谜题化 |

60%只能是实测结果，不能作为允许破坏真实性的构造指标。

## 5. R13-B之后的条件分支

- 若CoT/T3仍接近0错误：R13-C将批次控制总数替换为真实板球守恒关系，例如局总分、投手失分与byes/leg-byes差、搭档贡献和FOW端点的联合约束。
- 若Map&Make继续集中错在远端更新：增加批次级REVISE/RETRACT标注消融，验证错误来自更新算子还是文本理解。
- 若Direct错误而CoT/T3正确：保留当前难度，扩展独立根，避免继续谜题化。
- 若所有方法都出现相同错误：优先检查金标支持、输出契约和生成器指纹。
