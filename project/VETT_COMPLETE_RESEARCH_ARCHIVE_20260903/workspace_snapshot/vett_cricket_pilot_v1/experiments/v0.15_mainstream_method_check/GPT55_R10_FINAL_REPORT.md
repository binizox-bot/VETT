# R10 × GPT-5.5 六方法隔离盲测报告

## 1. 实验结论

R10 的六方法严格单元格错误率为 **24.70%–33.33%**，没有达到预设的 60%。六项均未完整恢复整场表格，整场精确率全部为 0。

误差审计显示，当前严格错误主要来自未定义清楚的复合字段。CoT、来源增强 T3、Map&Make 论文式和 Map&Make 增强式在 232 个格式明确的核心状态单元格上均为 **232/232 正确**。R10 已经可以测试表格实现和输出契约遵循，核心状态推理难度仍然不足。

当前版本不应作为“GPT-5.5、T3、Map&Make 推理失败率超过 60%”的论文证据。它适合作为 R11 重构前的诊断样本。

## 2. 盲测控制

- 模型：GPT-5.5。
- 输入：单个 R10 公开实例，23,679 词，11 张空表。
- 计分：336 个冻结目标单元格；公开模板另有 2 个金标为空的终局 `End`，不计分。
- 六种条件分别使用全新隔离上下文。
- 每个上下文只读取公开盲包和方法提示词。
- 禁止读取私有金标、证据、构造脚本、自测报告及其他方法预测。
- 六份预测先通过公开结构校验，再写入 SHA-256 冻结清单，随后首次读取金标评分。
- 温度等效设置：确定性单次诊断。

## 4. 核心状态切片

后验误差分析将契约含义明确的数值和类别字段组成 232 单元格核心切片。该切片不替代预先声明的严格主指标。

| 方法 | 核心错误 | 核心错误率 |
| --- | ---: | ---: |
| Direct | 18/232 | 7.76% |
| Direct + CoT | 0/232 | 0.00% |
| T3 直接整合变体 | 27/232 | 11.64% |
| T3 来源增强 | 0/232 | 0.00% |
| Map&Make 论文式 | 0/232 | 0.00% |
| Map&Make 范围/版本增强 | 0/232 | 0.00% |

这组结果说明：

1. Direct 和 T3 直接整合仍会在长文本状态恢复中产生真实数值错误。
2. CoT、来源增强元组和 Map&Make 原子化足以恢复本样本的明确核心状态。
3. 继续单纯增加文本长度、重放数量或修订数量，难以形成新的推理挑战。
4. 下一版应构造多个局部均可成立、只能通过远距离联合约束排除的候选状态。

## 5. 严格错误为何偏高

每种方法都有 62 个 Partnership 复合字段错误，来自三类字段：

- `Striker` / `Non-striker`：金标要求 `runs(balls)`，公开契约只给出列名。模型经常输出 runs。
- `Overs`：金标要求 `start-over–end-over`，模型经常输出持续长度。
- `End`：金标要求规范化的 `Dismissal Type (Batter)`，模型输出完整板球记法、落点比分或其他等价/不完整表示。

Map&Make 的 Fall of Wickets 多数差异来自 `18/1(4.6)` 与 `18/1 (4.6)` 的空格，以及球员名是否保留 `(c)`、`(wk)`。这些差异应由规范化器处理。

还有一个明确的数据错误：公开文本中没有 `Samuel Moore`，也没有 Referee 标签，私有金标却要求 `Referee = Samuel Moore`。该单元格缺乏公开证据，发布前必须删除或补充自然证据。

## 6. R11 必须执行的重构

### P0：修复评价有效性

1. 删除无证据 Referee，或在自然开场/赛后报道中补入裁判信息。
2. 将复合字段拆为原子字段：
   - Total → `Runs`、`Wickets`、`Legal Balls/Overs`；
   - Partnership contributions → 两名球员各自的 `Runs` 与 `Balls`；
   - Partnership span → `Start Over`、`End Over`；
   - Partnership end → `Dismissal Mode`、`Dismissed Batter`；
   - FOW At → `Team Runs`、`Wicket Ordinal`、`Over`。
3. 保留原始复合表作为第二个“表格实现轨道”，主推理指标只使用原子字段。
4. 提供公开 schema dictionary，明确每列单位、语义、合法值和规范化规则。
5. 评分器对空格、大小写、角色后缀和等价板球记法做预先声明的规范化。

### P1：提高核心状态难度

1. 为同一目标建立两个局部自洽候选世界；两者在单个段落、单张表和单类账本内都成立。
2. 最终判定依赖至少三处非相邻证据：事件类别、数值幅度、来源权限分别出现。
3. 删除“one higher/lower”“accepted figure”等明显教学式线索，改为自然广播纠错、延迟技术台确认和赛后官方摘录。
4. 设计部分修订：一次裁决只改变击球归属、extras 类型、合法球状态中的一项，其他项保持原值。
5. 设计跨事件耦合：修正事件 A 后，事件 B 的候选解释才会被守恒关系排除。
6. 让 checkpoint、replay、stale graphic 在语言形式上高度相似，身份只能通过参与者、局别、前后状态和合法球序列联合恢复。
7. 将最大 partnership、FOW、总分和 bowling conceded 绑定在同一隐藏事件选择上，避免分别计算即可通过。
8. 控制篇幅在真实解说范围内；难度来自依赖拓扑，避免继续机械扩写到更长文本。

### P2：三根小样本验证

从 220 场中另选 3 个未参与 R6–R10 的独立根，每根生成：

- 一个原子固定模式视图；
- 一个潜在模式视图；
- 一个自然多源/修订视图；
- 至少 100 个核心原子目标；
- 复合字符串只作为次级指标。

先完成双人独立恢复与裁决，再运行相同六种 GPT-5.5 条件。开发门槛建议设置为：至少三种方法家族的核心错误率达到 20%，遗漏率低于 10%，所有错误均可追溯至明确证据链。60% 可以作为观察结果，不能作为持续改写样本的硬目标。

## 7. 对数据集论文的含义

本次实验已经产生有价值的负结果：一个表面上包含大量重放、修订和长距离依赖的样本，仍可能被强模型完整恢复核心状态；不明确的输出模式会制造虚高错误率。该发现可以转化为数据集设计贡献：

- 区分状态推理错误与表格实现错误；
- 提供原子事实轨道和复合表轨道；
- 对每个单元格标注依赖图、版本链和规范化规则；
- 用双候选世界和最小判别证据衡量真正的非局部推理；
- 禁止无证据金标与后验格式惩罚。

这条路线比追求单场 60% 错误率更能经受 ACL/EMNLP/NeurIPS 审稿中的有效性、可恢复性和公平性审查。
