# 主流 Text-to-Table 方法检查：当前可报告结果

> 2026-08-19 更新：R10 的六种独立 GPT-5.5 盲测已经完成。正式结果与误差归因见 `GPT55_R10_FINAL_REPORT.md`。下文的 R2 与 R10 机制消融保留为历史对照，不再代表当前最高评测状态。

## 结论先行

现有证据不能声称“新数据集让 T3、Map&Make、CoT 的错误率均超过 60%”。当前可以严格报告三层：

1. **真实隔离模型盲测（R2）**：同一 GPT-5/Codex 平台、3 场、36 个固定模式单元格，覆盖 Direct、CoT、T3 两种和 Map&Make 两种。严格单元格错误率为 **22.22%–25.00%**，但标量事实错误率只有 **3.45%–6.90%**。这证明 R2 主要测到了复合字符串序列化错误，而没有充分击穿事实推理。
2. **R10 受控机制压力测试**：1 场、336 个单元格。六类错误机制联合时错误率为 **63.99%**；其中修订+重放+跨局别名为 **60.42%**。这些是对事件账本进行的确定性消融，不是任何命名模型或方法的实测成绩。
3. **R10 GPT-5.5 独立盲测**：六种条件的严格错误率为 **24.70%–33.33%**；在 232 个格式明确的核心状态单元格上，CoT、来源增强 T3 和两种 Map&Make 均为 **0% 错误**。严格误差主要集中在未定义清楚的复合字段。

因此当前正确判断是：**R10 已完成单模型诊断，核心状态难度不足，必须重构复合模式并增强候选状态拓扑。**

## 论文协议核对

### Direct / CoT

Direct 一次生成最终表；CoT 在同一任务上要求先逐步推理再输出表。T3 论文的附录 C.4 把二者作为零样本基线，温度设为 0。

### T3

T3 的正式管线是：文本到全局元组、元组整合、元组到表。论文默认在整合阶段生成代码；旧盲测运行的是论文中明确给出的“LLM 直接整合”消融，而不是默认代码路径。两者必须分开命名，不能都写作完整 T3。

### Map&Make

Map&Make 的三步是：命题原子化、模式提取、逐命题填表。R10 已提供空白模式，所以当前测试能够隔离值恢复，但不能完整测试 Map&Make 最强调的潜在模式发现。正式数据集还需增加无模式视图。

### 训练式方法

Text-to-Table seq2seq 与 Seq2Seq&Set 是合理的训练基线，但现在没有冻结训练/开发/测试划分，也没有训练检查点。此时强行训练会污染测试集，并产生不可比较数字，所以列为阻塞而非伪造结果。

## R10 为什么可能更难

R10 有 23,679 词、888 个片段、436 个原子事件、153 次同事件重放、60 条修订链、6 个区间检查点和 55 个隐式状态链接。336 个计分单元格中有 330 个是挑战单元格。它针对的不是单一算术，而是事件身份、版本、局别范围、合法球状态和跨表守恒的联立恢复。

公开空表实际含 338 个空白；其中两局最后一段 partnership 的 `End` 金标也为空，因此明确排除，最终计分分母为 336。报告、评分器与 `scored_cell_ids` 三者使用同一分母。

| R10 受控故障 | 错误率 | 解释边界 |
| --- | ---: | --- |
| 信任暂定图卡 | 36.61% | 机制消融 |
| 把重放算作新事件 | 52.68% | 机制消融 |
| 把检查点算作新事件 | 44.94% | 机制消融 |
| 只恢复类别、不恢复幅度 | 20.54% | 机制消融 |
| 只恢复幅度、不恢复类别 | 28.87% | 机制消融 |
| 修订+重放+跨局别名 | 60.42% | 机制消融 |
| 六类错误联合 | 63.99% | 机制消融 |

这些数字只说明：若方法犯相应错误，会影响多少最终单元格。它们不能说明 T3 或 Map&Make 实际会以该概率犯错。

## 已准备的正式运行入口

`prepare_r10_eval.py` 只读取公开 R10 文件，生成与现有 OpenAI-compatible 运行器兼容的盲测 JSONL。`score_r10_predictions.py` 在模型输出冻结后读取私有金标，计算单元格、行、表、整场、遗漏、幻觉以及按表型和证据操作分桶的结果。

诊断运行命令：

```bash
python prepare_r10_eval.py \
  --public ../v0.14_r10_fourth_root_implicit/instance/r10_public.json \
  --output blind/r10_blind.jsonl

python ../../scripts/run_openai_compatible_baselines.py \
  --blind-inputs blind/r10_blind.jsonl \
  --config ../../baselines/experiment_config_v0.3.json \
  --output-dir runs \
  --base-url "$VETT_LLM_BASE_URL" \
  --api-key "$VETT_LLM_API_KEY" \
  --model "$VETT_LLM_MODEL" \
  --max-tokens 20000
```

外部端点运行器仍保留用于后续多模型实验；本轮 GPT-5.5 结果来自六个相互隔离的模型上下文，并已先冻结后评分。

## 发表级门槛

在引用命名方法错误率前，至少需要：

- 先完成 R10 的来源支持审计、双人可恢复性标注和唯一解裁决；
- 冻结不少于 30 个独立比赛根的诊断集，再冻结更大的隐藏测试集；
- 至少 3 个相互独立的模型家族，同一主干上运行所有提示方法；
- 温度 0 主结果，并用 3 次重复报告随机性敏感性；
- T3 同时运行默认代码整合路径和直接整合消融；
- Map&Make 同时评测固定模式与潜在模式两种视图；
- 报告 bootstrap 95% 置信区间、配对检验、成本和解析失败率；
- 任何难度调节只看开发集，隐藏测试集只能在冻结后运行一次。

## 当前决策

**保留 R10 作为诊断样本，不直接进入发布集。** 下一步按最终报告中的 P0–P2 路线构造三个新根：先原子化复合字段与修复无证据金标，再围绕双候选世界和远距离联合约束增强核心状态难度。
