# DSH 执行指令｜VETT 本地证据核对与长文联动长任务

请在已有 VETT 项目执行这轮任务。用本机已经装好的 Qwen2.5 7B、Llama3.1 8B、Gemma2 9B，外部 API 0 次。目标是让小模型做短小、可查原句的核对，把能核实的证据接回 220 场长文表格和 R28，然后用少量对照判断小模型在哪一环节出错。保留 220 场、原记分表、R28 与历史输出。新增内容放在独立目录，完成后交付可回滚的补丁和报告。

按约 90 分钟规划，最长 120 分钟，最多 132 次本地模型请求，重试计入上限。先估实际速度，再排后续批次。任务做完可提前结束。请实际跑完时间内能完成的批次，结束后自动复算并写报告。

## 1. 先复算两场历史试点，不调用模型

定位 `VETT_INTEGRATED_20261113` 或本机项目根，读取已有研究材料、两场联动试点及 `match_0003`、`match_0012` 的 36 条原始响应、6 条整表锚点和实际评分脚本。新目录建议 `analysis/vett_local_evidence_long_run/`。优先复用已有 runner 和 schema。

- 为每条历史响应重建 `match_root × model × method × condition` 唯一键。分别生成两名投手数值同时正确、同局 total 正确、三项全对三列。联合分在同一方法、模型与比赛内做维持、改判布尔交集，三条件全对再加入无通知。每个口径独立复算，验证联合分不超过任一组成条件的正确数。按模型汇总须与总计对齐。
- 逐条标明程序提出转移、程序拒绝、实际执行、执行后两边变化及是否与金标相符。用模型抽出的旧值计算执行前后差，分别记录误执行与错误旧值。必要时另报最终数对是否恰好等于基于金标旧值的一减一加。没有执行证据就标未确认。
- 对整表 top-2 逐场核对金标排名、原文证据、预测实体和预先允许的别名。分清目标原本在金标 top-2 但预测选错人、目标原本不在金标 top-2、键缺失或实体无法解析、以及实体正确但数值错。排名规则仍有歧义就保留该状态。
- 报告历史原数、复算数、分歧来源、未能确认的细节。若原始文件缺失，保留报告里的矛盾为待核，继续做发布版证据审计。此阶段不要重跑旧模型请求。

## 2. 建一个小任务队列，让三个模型各自找证据

从现有长文发布版和表格索引按比赛根去重。先用已审计的六场定位候选，另从 220 场抽取未参与调试的根。上限 12 个比赛根，每场最多两局。用固定排序或固定种子抽样，保留候选、排除理由、开发或未调试状态。尽量覆盖局终比分、局中比分干扰、双方或两局数值相近、缺局终句等情形。已知线索如 `0008`、`0010`、`0012` 的比分，只用于内部查文件和比对，绝不放进核对提示。

每条小任务只针对 **一场的一局**，从发布版 commentary 核对该局终局总分与终局 wicket 两个紧密相关的字段。输入包含本文和所问局别，可用该局球队作身份提示，提示中不要给记分表、其他模型结果、候选数值或金标。全文放不下时优先选能装入的样本。必要时将候选证据窗口用作辅助搜索，明确其范围；窗口找不到证据只标未找到，全文缺证须另核实。

给本地核对模型统一使用下面的任务说明，按项目格式替换局别、球队、字段 ID 与正文。跨模型独立运行，彼此看不到回答。

> 请仅根据给定比赛解说，找指定球队在指定局结束时的总得分和已出局数。先给能支持每个字段的原文短引，再给对应值。若不是终局、局别不明或无法确认，请保留最相关的原句并说明是哪种情况。未找到足够证据时返回 UNKNOWN。不要用常识补数字，也不要把另一局或局中比分当成该局终局。只输出 JSON。每个字段使用 `status`（explicit、derived、not_found、conflict、ambiguous）、`value`（整数或 UNKNOWN）、`quotes`（逐字原文字符串数组）和 `reason`（一句话）。如为 derived，列出原文支持的运算。两个字段允许共用同一句。

最多 **12 场 × 2 局 × 3 模型 = 72 次**。只发实际存在且冻结的局别。预留缺证样本，模型检索结果与证据标签是审计记录，不能直接当作金标。记录相同原句、答案一致但依据不同、模型分歧及共同错误。

用脚本与人工复核各自处理能确定的部分。

- 脚本定位逐字原句，保存文本哈希、行号或字符范围。规范化匹配只能辅助定位，最终证据引用必须确实出现在发布版原文。若命中多处，保留候选位置并核对局别上下文。
- 能机械核实的直读终局句，检查球队、局别、终局语义、得分与出局数的字段对应，再与记分表核对。句子存在和数值吻合，仍须满足这些语义条件。三模型一致只增加复核优先级。有争议、难判语义、跨句推导和声称全文缺证的样本进入人工队列，模型没有找到证据本身不能证明缺证。
- 证据状态单列：自动规则核实、待人工复核、已人工复核。人工未完成时明确记实际数。保存无模型预测时的脚本候选与命中数，复盘模型补找了哪些证据。79/258 的历史口径单列保留。

## 3. 将查实的原文证据接回整表和 R28

首选局终 `total_runs` 和 `total_wickets`。每条链接写 `match_root`、局别、球队 ID、项目原有表格字段 ID、证据跨度、文本哈希、R28 题号或新增候选题 ID。相同发布版输入支持的链接，与只有比赛根及字段相同的重渲染链接分别报数。对两场旧投手改判题保留其重渲染来源与证据局限，纳入本轮零调用复算。

按时间最多选 4 场做联动对照，每场选一局。入选依据是同一发布版原文、同一格子、证据明确且有可比字段映射。冻结样本和评分，再读这一阶段的模型预测。报告候选是否在前阶段被自动核对、是否用作提示调试。若全是已调试材料，仅作开发结果。每个入选样本保存正文的实际渲染提示和校验哈希。

| 条件 | 输入 | 模型任务 | 用途 |
|---|---|---|---|
| A | 完整发布版原文 | 直接输出同一局的总得分与总 wicket | 建立长文里的字段基线 |
| B | 从 A 逐字摘录的核实证据，保留回答需要的局别信息及必要上下句 | 与 A 相同题干及字段输出 | 测试提供现成证据后是否救回；摘录依赖已核实证据，当离线诊断报告 |
| C | 与 A 完全相同的完整发布版原文 | 同一数值目标，另要求先引用支持句再填写 | 测试一个轻量改动能否找到依据并改善数值 |

A/B/C 最多 **4 场 × 3 模型 × 3 条件 = 36 次**。B 的摘录只允许删减或提取原文，不改写、不添加答案、标题里不标正确句。A 与 C 锁定正文、目标字段及模型配置，比较数值同时分报 C 的证据有效率和长度成本，不用 C 的额外证据字段处罚 A。A 与 B 的差异表示给出精选证据后的表现，无法单凭结果区分长上下文搜索困难、干扰或提示位置等具体成因。A 与 C 的差异归于本次提示改动，不能单凭引用证明模型内部推理过程。

整表锚点从同版本发布版正文和既有 43 字段任务按字段提取，优先复用可核对的历史原始预测。缺少且预算允许时补做，最多 **4 场 × 3 模型 = 12 次**。真正同格要求相同发布版输入、比赛、局别、球队与字段定义。若耗时允许且有完整可配对锚点，可对同一批中的最多 4 场，用整表原任务加同样的“先定位局终证据再填这两个字段”做 C 的小范围回投，最多另加 **12 次**。在看整表回投结果前冻结样本与提示。保留原 43 格输出结构，对目标字段单列收益，对其余有证据的字段检查是否出现退步。无法可靠同口径比较的整表回投明确标未运行或不可比。

本阶段看四种具体结果。

- **A 错、B 对**：原文已确认有答案，保存为提供证据后可救回的候选，对原始错误仅标可观测表现。
- **A 错、B 也错**：核查模型引用或输出是否把同句的 runs 和 wickets 对调，是否读错数词。若语义证据仍不够，回到证据审计更正状态。
- **A 对、C 错，或数值对、引用错**：记录损害与证据无效，即使 C 的平均分增加也分别报。
- **模型在整表错、A 对**：记录同字段在任务范围变化后表现不同。只有实际完成整表前后配对，才报告整表方法提升。

证据无争议的同格样本不足时，按实际数量交付。不得用重渲染文本填作发布版同输入样本，不重开整个数据集构建。

## 4. 后台运行、保存、恢复

- 优先复用项目后台 runner。检测现有任务进程和 GPU 负载，避免重复启动同一矩阵。先跑一组小任务，记录实测 P50 耗时和每模型开销，再规划 90 分钟内的批次。尽量保持三模型对同一场的完整对照，每完成一场立即落盘。资源紧时减少入选比赛数或跳过可选整表回投，不拆已开始的核心配对，除非达到硬时间限制或服务失败。
- 记录模型 tag、digest（可得时）、量化、温度、seed、可用上下文、实际输入长度、输出 token、耗时和终止原因。独立会话，避免引入其他条件历史。核查 runner 实际渲染文本和超长情况。确认同条件允许的格式别名在评分前冻结。
- 以 `阶段 × 比赛根 × 局别 × 模型标识 × 条件 × 提示哈希` 作为唯一任务键。原始输出写入后再更新完成状态。模型空答、JSON 失效、截断保留为结果。只有连接中断、服务超时等基础设施异常才允许有限重试，每个位置最多一次，保留原日志。达到 132 次总请求或 120 分钟立即停止发新请求，按剩余时间保存状态并输出截至结果。
- 每 10–15 分钟更新 `PROGRESS.md`，写已完成、复用、失败、待跑、耗时、预计下一批及输出路径。若采用脱离终端的进程，先确认存活、日志前进和首批落盘。任务完成须运行零调用复算并生成报告。若整场停在不完整矩阵，把缺失条件及原因列清楚，完整配对作为主比较，同时报告覆盖率。
