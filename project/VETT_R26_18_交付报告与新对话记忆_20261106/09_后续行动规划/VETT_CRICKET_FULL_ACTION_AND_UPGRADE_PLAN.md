## 2. 不可突破的治理边界

### 2.1 永久禁止事项

- 不读取、复制、打印或写入报告任何API密钥。
- 不因本地存在密钥、配置或历史余额而推定费用授权。
- 不自动重试、自动续跑、自动Pilot20、自动第二模型或自动220场外测。
- 不覆盖或删除历史失败运行、原始响应、checkpoint或报告。
- 不把不同数据版本、协议版本、场次覆盖、模型版本或后验回放合并成一个正式成绩。
- 不把provider错误、传输错误、协议错误记作语义零分。
- 不把Oracle满分、静态门通过或流式预检当作强模型经验结果。
- 不把R26.18后验回放追溯改写为历史正式通过。
- 不声称220场R26.15已经最终物化、人工双标或正式发布。
- 不声称强模型主指标已经稳定不高于65%，或四个相邻等级差已经稳定达到8个百分点。
- 不通过单纯增加长度、无关噪声、冲突数量或不自然表达制造“难度”。
- 不为了得到更好曲线而修改事实金标、降低证据标准或事后改阈值。

### 2.2 一次授权只覆盖一个阶段

以下动作分别需要独立、明确授权，不能继承：

1. R26.18 Sentinel5；
2. Sentinel失败后的任何新运行或可用性续跑；
3. 第一模型家族Pilot20；
4. 第二模型家族Pilot20；
5. shadow candidate的外部测试；
6. 任何更大规模模型盲测；
7. 数据候选变更；
8. 220场内部物化；
9. 对外发布。

数据变更授权不包含物化，物化授权不包含发布，发布授权也不能反向授权修改数据。

授权应明确：数据版本、协议、模型、场次、费用上限、重试策略、输出目录和停止条件。

### 2.3 数据正确性永远优先于难度

“困难但有歧义”“困难但无充分证据”“困难但金标不稳定”都属于数据质量失败，不属于成功的高难度设计。难度只能来自可解释的认知负担：实体绑定、来源权限、时间顺序、规则组合、状态传播、反事实重算和最小证据图构造。

## 4. 统一质量模型：同时看难度、准确度与可发布性

### 4.1 正确性层

必须分别验证：

- 事实字段是否来自可靠来源；
- 冲突字段是否被保留但未强猜；
- 潜在状态是否由板球规则正确推出；
- 反事实是否只改变一个原子事实并完整传播；
- 正证据与排除证据是否角色清晰；
- 类型边方向和关系是否正确；
- `conditions_rule`是否连接被改事实与全部受影响规则；
- 证据图是否无环、端点合法且在冻结输出上限内；
- 独立重建是否逐字节一致。

正确性红线：Oracle的事实、反事实和证据链闭环必须为100%；任何非预期下降都阻断外测。

### 4.2 难度层

冻结主指标是`decision_field_level_macro_accuracy`：每题12个归一化事实字段，先在私有等级内平均，再对L1–L5等权平均。

冻结目标：

- 强模型主指标区间：45%–65%；
- L1最低准确率：60%；
- 目标相邻下降：8个百分点；
- Sentinel5只做方向筛查：至少3个相邻变化为正向下降，平均相邻下降至少8个百分点；
- Pilot20正式门：四个相邻点估计均至少下降8个百分点，且至少3个相邻差的95%置信区间下界大于0。

### 4.3 证据与推理层

以下指标必须作为伴随指标，不得取代主难度指标：

- 事实整记录exact；
- 信息字段和值平衡信息字段准确率；
- 潜在状态、反事实字段和反事实整记录；
- paired factual-counterfactual exact；
- 正证据span F1；
- 排除证据F1；
- typed-edge F1；
- 内容依赖edge F1；
- evidence-chain exact；
- factual+evidence-chain exact；
- Brier score；
- 未知证据引用率。

这些指标用于判断失败发生在事实恢复、冲突排除、规则应用、关系方向、内容依赖、完整链或置信校准，而不是用于事后挑选最好看的数字。

### 4.4 可识别性与反捷径层

每个候选都必须重新检查：

- 问题文本本身是否能预测答案；
- 多数值先验是否掩盖真实错误；
- 文档类型、ID形态、位置、角色措辞是否泄漏证据角色；
- 固定关系模板是否能重建完整图；
- 私有等级是否能由公开表面直接分类；
- 情景家族与等级是否混杂；
- 证据任务是否被输出格式而非语义能力主导。

### 4.5 输出可靠性层

R26.18要求并列报告四轨：

1. provider可用性；
2. 硬协议合法性；
3. 输出服从性；
4. 集合语义能力。

完全相同的span或边重复项按集合只计一次，但受影响题必须标为nonconformant。合法形状但不存在的span保留为语义假阳性。非法JSON、缺题、非法关系、畸形ID、外来节点和原始数组超限仍是硬失败。

### 4.6 人工与发布层

机器一致性不能替代：

- 板球规则专家判断；
- 自然语言可读性与自然度；
- 证据最小性的人类判断；
- 来源、许可和可再分发性；
- public/private边界和泄漏检查；
- 独立环境复现。

## 5. 四条版本轴与不可变工件

后续工作必须同时记录四个不同身份：

1. **数据版本**：文本、题目、事实、金标、证据成员或边发生变化，必须创建新数据候选；R26.15原目录永远不可原地修改。
2. **评测协议版本**：JSON结构、规范化、硬失败定义或评分语义变化，只升级协议，不得描述为数据变难。
3. **实验运行ID**：每次外部执行使用唯一run/cohort ID和全新空输出目录，不得覆盖终态运行。
4. **报告版本**：纯文档修订不改变数据或实验身份，报告必须指向确切输入和哈希。

建议后续新增机器可读的`PROJECT_STATE.json`，至少包含：当前数据候选、协议、阶段、状态、授权位、最新基线manifest、最新准入、开放阻塞项和下一项允许动作。状态更新必须伴随前后差异，不能只手改一个状态字符串。

| 45%–65%，L1≥60%，方向筛查通过 | 难度值得扩大验证 | 申请第一模型Pilot20 |
| >65% | 可能偏易 | 登记已被模型解决的机制假设，Pilot20验证；不改题 |
| <35%或L1<60% | 地板效应风险 | 禁止加难；Pilot20前先审查协议负担和L1/L2设计 |
| 35%–45% | 未注册自动决策的灰区 | 扩大诊断或审查负担；不得临时发明阈值 |
| 45%–65%但曲线不通过 | 等级稳定性存疑 | 登记弱相邻对/倒置假设，由Pilot20确认 |
| 事实合适、证据链极低 | 事实难度可能合适，证据任务困难 | 拆分检索、关系、内容依赖和输出服从性；不全局加难 |
| 服从性低、集合语义可评分 | 输出纪律问题 | 并列报告；不得归因于数据语义难度 |

#### 输出

- `SENTINEL5_FINAL_VALIDATION.md`
- `SENTINEL5_RESULT.json`
- 四轨报告与切片表；
- `ERROR_HYPOTHESIS_REGISTRY.json`；
- `DECISION_RECORD.md`；
- 更新后的实验账本与暴露账本。

### 阶段3：第一强模型家族Pilot20

#### 进入条件

- 完整Sentinel5有足够信息增益；
- 数据、协议和主指标保持冻结；
- 20场、100题和5×5锚点设计完整；
- 不得根据Sentinel分数重选更有利的20场；
- Pilot20成本、模型和失败策略另行预注册并单独授权。

#### 固定设计

- 20场、100题；
- 每场L1–L5各一题；
- 每级20题；
- 五锚点家族×五等级的25个单元完整平衡，目标每格4题；
- 同一R26.15文本、题目、金标、公开输入和R26.18评分语义。

#### Pilot20正式资格

- 20场和100题全部返回，匹配单元无缺失；
- 所有runner batch状态为`OK`，无截断、JSON修复或硬schema/图错误；
- canonical duplicate可以表现为`OK + conformance warning`并进入集合语义评分，但必须并报服从性；
- 从`INVALID_OUTPUT`恢复的事实或语义只可作为诊断，不能补成正式Pilot20；
- provider/传输失败、部分子集、后验回放和不同协议运行不得合并。

#### 统计合同

- 以比赛为分块单位，五个等级随比赛一起重采样；
- 10,000次bootstrap；
- 固定种子26091；
- 双侧95%百分位区间；
- 线性插值位置`(n-1)*p`；
- 四个相邻点估计下降均至少8个百分点；
- 至少三个相邻差的95%下界大于0。

辅助锚点标准化诊断只能解释情景组成，不能替代上述主门。所有探索性切片必须标注探索性，不得成为事后新发布门。

#### 一个模型家族之后的权限

只有在所有runner batch均为`OK`且不依赖诊断恢复、同一注册错误机制至少影响4题、问题在至少2个锚点复现且报告保持锚点平衡时，才允许构建一个**shadow candidate**。它不能覆盖R26.15，也不能晋升为正式候选。问题可以属于全局偏易、弱相邻/倒置或地板效应，但必须走各自的冻结触发路径。

### 阶段4：shadow candidate的局部优化——仅在权限满足时

#### 真正允许优化的条件

- 至少一个强模型家族完成有效Pilot20；
- 问题来自冻结主指标和预注册机制；
- 不是单场、单锚点、Oracle、结构指数或小模型触发；
- 不是provider、格式、输出容量或评分代码问题；
- 修改目标和影响范围在动手前登记。

#### 三类合法触发路径

| 触发 | 允许的shadow方向 | 不允许的解释 |
| --- | --- | --- |
| 主指标>65% | 只修改模型正确回答的合格题所对应的已注册机制；保留事实金标和不相关低等级 | 不要求强行套入某个弱相邻对；不能全局加难 |
| 某相邻下降<8点或出现倒置 | 只修改弱相邻对的上一级，并使用下表对应机制 | 不能同时改多个等级 |
| 主指标<35%或L1<60% | 禁止加难；只减少L1/L2中一个已诊断负担，形成减负shadow | 不能继续增加证据、噪声或规则负担 |

#### 四个相邻转移预注册机制

| 弱相邻对 | 上一级 | 允许机制 | 完整激活条件 | 每题最多新增决定性span |
| --- | --- | --- | --- | ---: |
| L1→L2 | L2 | 双键权限选择：真实性键与事件版本/锁定键分别出现 | 有效L1→L2下降<8点，且L2准确率高于冻结带 | 2 |
| L2→L3 | L3 | 同规则跨事件绑定碰撞：必须依赖玩家、over、时间身份链 | 有效L2→L3下降<8点，且错误由跨事件绑定主导 | 1 |
| L3→L4 | L4 | 修订优先级与锁定时间组合：任一条件单独都不足 | 有效L3→L4下降<8点，且权限或顺序错误主导 | 2 |
| L4→L5 | L5 | 上游原子干预传播到交付有效性、dismissal和多个账本字段 | 有效L4→L5下降<8点或反事实表现平台化，且不存在地板效应 | 2 |

#### 修改约束

- 弱相邻路径只改相邻对的上一级；全局偏易路径只改被正确解决的合格机制；地板路径只做L1/L2单负担减法；
- 新增决定性span严格服从上表逐机制预算，L2→L3不得超过1，其余相邻机制不得超过2；
- 插入span触达率不超过2%；
- 不触碰任何R22受保护目标或受保护证据span；
- 每场被改变的基础span比例保持低于1.5%，除非另有事前审计并冻结的新合同；
- 保持单一原子反事实；
- 保持事实与反事实金标正确；
- 不改变无关的低等级；
- 禁止只加长度、无关噪声或答案风格提示；
- 必须保持注册证明和公开表面证明唯一；
- 必须重新通过元数据、语义捷径、语言、锚点平衡、独立重建和零请求容量门。

#### shadow首次外测

首次外测只覆盖受影响机制的五个匹配锚点—等级单元，不直接重跑完整Pilot20。它使用新数据身份、新run ID、新空目录和单独费用授权。原R26.15成绩不能移植为shadow的正式成绩。

### 阶段5：第二强模型家族复验

#### 模型选择原则

- 必须是不同模型家族，不是同一权重的另一个API端点；
- 在看结果前冻结具体模型版本、provider、参数、上下文、价格和日期；
- 能支持长上下文和可审计结构化输出；
- 不根据“更可能得到理想分数”选择模型；
- 使用与第一家族相同的原始R26.15 20场和评分合同。

#### 为什么第二家族仍测试原R26.15

如果第一家族结果已经参与shadow设计，第二家族必须先在未改变的R26.15上独立验证触发方向，避免用已调数据制造跨模型一致性。

#### 两家族决策矩阵

| 证据组合 | 决策 |
| --- | --- |
| 两家族均在目标区间且曲线通过 | 冻结R26.15难度，进入220场前门 |
| 两家族均>65%，同一机制偏易 | 可考虑晋升定向shadow，但先做新shadow Sentinel |
| 仅一家>65% | 记录模型特异性，不晋升修改 |
| 两家族同一弱相邻对、每家族至少2个锚点支持 | 可考虑相邻上一级shadow |
| 倒置只出现在一家 | 不全局改题，保留模型特异诊断 |
| 任一家L1<60%或总体<35% | 禁止增加难度；检查地板与协议负担。若两家族同向复现，可考虑L1/L2单负担减法shadow，且fresh shadow Sentinel必须证明地板效应已消除 |
| 两家族方向相反 | 不用平均数掩盖差异，回到锚点与机制分析 |
| 区间过宽或大量跨0 | 承认证据不足；不得降低门槛 |

#### shadow晋升门

两个强模型家族必须同向复现触发条件，每家族至少2个锚点支持。增加难度的shadow要求原证据不存在L1或全局地板效应；减负shadow则必须由fresh shadow Sentinel证明地板效应已消除。随后还必须完成全新的shadow Sentinel。只有该Sentinel及所有静态门通过，shadow才有资格晋升为新数据候选；R26.15仍保留不可变。

### 阶段7：人工复标、自然度与领域专家验收

#### 7.1 标注者角色

建议至少分为三种角色：

- 标注者A：板球规则与记分知识；
- 标注者B：数据/证据图与结构化标注能力；
- 仲裁者C：能够同时判断板球规则、来源权威和证据充分性。

标注者应对模型输出和私有难度标签盲化，避免被模型错误或预期曲线诱导。

#### 7.2 分层人工流程

1. **规范试标**：先用25题五场×五级样本检验说明书和工具，不用于发布一致性结论。此项应在阶段6之前完成。
2. **pilot全复标**：最终候选的20场100题全部独立双标，覆盖事实、状态、反事实、正/排除证据和边；它是阶段6进入门。候选若因shadow或系统性修复改变，所有受影响pilot题必须重新双标。
3. **全量单审**：最终1,100题至少完成一次独立人工核验。
4. **全量双标抽样**：对剩余1,000题按等级、锚点、情景、规则、冲突负担和文本长度预注册分层样本；样本量依据试标错误率和目标置信上界确定，不能事后挑选。
5. **强制双标集合**：所有新增/修改题、L4/L5、高冲突、高图规模、自动门告警、历史失败关联题和重复控制必须双标。
6. **专家仲裁**：任何事实、规则、因果或最小证据分歧进入第三方仲裁，不允许用多数票掩盖规则争议。
7. **修复与重建**：人审缺陷只能进入新数据版本；系统性生成器缺陷必须修生成器并全量重建。完成修复、回归和必要的重复人审后，在两个干净环境中重新物化并冻结最终manifest、拆分与发布哈希。

#### 7.3 人工检查维度

- 事实值与来源；
- 冲突来源的权限和作用域；
- 事件身份链；
- 活球/死球、No-ball/Wide优先级和dismissal有效性；
- 单一干预和反事实传播；
- 正证据是否充分且最小；
- 排除证据是否确属同事件冲突；
- 边关系和方向；
- 题干是否清晰、无答案提示；
- 文本是否自然、无机器退化或不必要重复；
- 公开输入是否意外包含私有标签或金标。

#### 7.4 人工准入门

现有设计已经登记：两位专家对值、作用域、规则版本和最小证明的一致率至少达到98%，所有分歧必须在发布前仲裁。该门应作为最低要求继续冻结。

正式标注前必须在独立人工合同中固定：双标抽样框、分层变量、随机种子、样本量/功效规则、98%的计算单元和分母、是否对四个维度分别设门、置信区间或可接受错误上界。保守做法是分别报告值、作用域、规则版本和最小证明的一致率，不能用大量容易字段合并稀释困难维度。

同时必须报告字段精确一致率、状态/反事实整记录一致率、正/排除证据集合F1、类型边与内容依赖边F1、自然度缺陷分布、仲裁率，以及适用于分类判断的Cohen's kappa或Krippendorff's alpha。标注者一致率与经来源/专家仲裁后的金标准确性必须分开报告。除已有98%门外，如要增加新的数值发布门，必须在查看正式双标结果前由用户和领域专家批准并冻结。

关键规则/答案矛盾为0容忍。任何系统性规则错误、来源权限错误或金标错误均直接阻断发布，不因总体一致率高而忽略。

### 阶段8：发布候选、论文与长期维护

#### 最终盲测与论文主张门

必须区分两种证据强度：

- **220扩展前门**：两个强模型家族在20场Pilot20上完成冻结评测，足以决定是否冻结机制并进入220内部物化。
- **最终五级稳定性论文主张**：20场pilot已经参与设计与校准，不能单独代表220场泛化难度。现有长期稳定性规范要求至少每级100个独立盲测题、每个相邻差的比赛分块95%下界大于0、私有等级与经验难度Spearman相关至少0.85，并在至少三个强模型家族保持等级顺序；规范还要求在最终等级主张前覆盖至少一个经济型、一个中型和三个强模型家族。

因此：

1. 若论文要声称最终220场上的模型表现、相邻等级稳定性或跨模型泛化，必须在最终数据哈希上预注册独立盲测样本、模型面板、功效、预算和统计合同，并另行授权；重复控制不计入独立样本。
2. 若资源不足而不做上述盲测，论文只能声明“20场开发/校准pilot上的结果”，不得外推到220场。
3. 若最终候选是shadow，所有R26.15模型结果只能作为前代触发证据；最终版本的正式成绩必须绑定shadow/后继候选的确切哈希。
4. 如果项目决定用更低成本的新标准替代长期稳定性规范，必须在查看盲测结果前形成版本化ADR和新合同，不能由本计划静默覆盖旧要求。

独立盲测不是阶段6物化的自动付费动作。应先完成抽样、功效和费用设计，再逐阶段授权。

#### 发布包最低内容

1. 完整数据卡：来源、任务、字段、拆分、适用/禁用场景、限制和偏差；
2. 来源—许可—再分发权限矩阵；
3. 数据和代码许可证；
4. `CITATION.cff`或等价引用文件；
5. 可移植的相对路径manifest和全部SHA-256；
6. Python版本、依赖锁和干净环境复现记录；
7. public/private白名单打包器；
8. schema、字段、协议和评分说明；
9. 两个模型家族的完整正式Pilot20与置信区间；
10. 人工标注规范、一致性、分歧和仲裁记录；
11. 变更日志、迁移说明、已知问题；
12. 无密钥、无本机绝对路径、无私有金标和无受限响应全文检查；
13. 217独立根与3重复控制的统计边界；

## 7. 问题分级与统一升级路径

### P0：立即停止并隔离

适用情形：密钥泄漏、未授权费用、冻结候选被覆盖、public包混入private gold、受限原始响应泄漏、来源许可明确禁止使用。

处理顺序：

1. 立即停止进程；
2. 保留日志和现场，不覆盖文件；
3. 记录时间、影响范围、路径和哈希；
4. 隔离输出；
5. 通知用户决定轮换密钥、恢复备份、作废运行或停止发布；
6. 问题关闭前禁止外测与发布。

### P1：阻断当前阶段

适用情形：输入哈希漂移、Oracle不闭环、数据/协议版本不匹配、硬协议失败、来源或规则版本无法确认、匹配设计缺单元、人工发现系统性金标错误。

处理原则：只修对应层。数据问题建立新候选；协议问题建立新协议；provider问题只记可用性；评分问题保留原始响应做版本化本地重放。修复后必须用新版本、新run ID和必要的新授权重新准入。

### P2：允许分析但禁止直接扩展

适用情形：主指标过高/过低、等级差不足、曲线倒置、证据链极低、服从性差、不同模型方向不一致、人工分歧集中。

处理原则：先完成字段、等级、锚点、关系和情景切片；只登记预注册局部假设；遵守Pilot20调整权限；不全局加长度、噪声或冲突。

### P3：文档与可移植性缺陷

适用情形：标题陈旧、绝对路径、缺环境锁、数据卡不完整、命名不一致。

处理原则：通过独立报告版本修复；运行链接、manifest、路径与敏感信息检查；不得更改数据或成绩。

## 9. 数据准确性与难度优化的标准闭环

任何优化必须按以下十步执行：

1. **发现**：由有效Pilot20、人审或确定性测试发现问题；
2. **归类**：判断是数据、协议、模型、测量、语言、统计还是provider问题；
3. **定界**：列出受影响题、等级、锚点、关系和字段；
4. **登记假设**：在看新结果前记录根因和预期变化；
5. **检查权限**：确认当前阶段是否允许数据修改；
6. **构建shadow**：复制新候选，不原地改R26.15；
7. **本地闭环**：Oracle、countermodel、变异、反捷径、语言、容量和确定性重建全部通过；
8. **最小外测**：只测受影响的注册单元，使用新授权和新run；
9. **跨家族确认**：防止对单一模型过拟合；
10. **晋升或丢弃**：依据预注册门决定，失败shadow保留证据但不晋升。

一次优化只验证一个主要假设。禁止同时改题面、金标、难度机制和评测协议，再用一个新分数解释全部变化。

## 13. 项目状态机

必须维护两条独立状态轴，不能互相替代：

1. `admission_status`：由现有准入工具从工件计算，例如当前的`LOCAL_PROTOCOL_PASS_EXTERNAL_EXECUTION_BLOCKED`。后续模型不得手工改写。
2. `lifecycle_phase`：用于描述项目规划阶段，例如`STAGE0_BASELINE_PASS`或`PILOT20_ONE_FAMILY_COMPLETE`。

正常生命周期路径：

```text
STAGE0_BASELINE_PASS
→ SENTINEL5_AUTHORIZED
→ SENTINEL5_COMPLETE_VALID
→ PILOT20_ONE_FAMILY_COMPLETE
→ PILOT20_TWO_FAMILIES_COMPLETE
→ DATASET_DIFFICULTY_FROZEN
→ FULL_220_INTERNAL_MATERIALIZED
→ HUMAN_QA_PASS
→ FINAL_DATASET_HASH_FROZEN
→ FINAL_BLIND_VALIDATION_OR_CLAIM_LIMITATION_FROZEN
→ RELEASE_CANDIDATE
→ PUBLICATION_READY
```

任一生命周期阶段可转入：

```text
BLOCKED_AUTHORIZATION
BLOCKED_PROTOCOL
BLOCKED_PROVIDER_AVAILABILITY
BLOCKED_DATA_QUALITY
BLOCKED_COST
BLOCKED_LICENSE
SENTINEL5_INCOMPLETE_HARD_FAILURE
INVALIDATED_BY_DRIFT
```

provider/传输失败不得归入`BLOCKED_PROTOCOL`，不完整Sentinel也不得伪装成完整阶段。解除阻断必须有新的决策记录、输入哈希和重入门，不能只改生命周期名称，更不能覆盖机器生成的`admission_status`。

## 14. 里程碑和完成定义

### M0：本地冻结基线——已完成

定义：测试、哈希、preflight和admission一致，外部执行阻断。

### M1：正式Sentinel5完成

定义：五场25题同协议完整可评分，原始工件、费用和四轨报告齐全。它只完成筛查，不完成论文校准。

### M2：第一家族Pilot20完成

定义：20场匹配设计完整，比赛块bootstrap与所有不确定性工件齐全；允许在满足条件时构建shadow，不允许晋升。

### M3：双家族220扩展前门完成

定义：第二不同家族在同一R26.15与协议上完成Pilot20；方向一致性和模型差异明确；任何shadow晋升符合调整权限并通过新Sentinel。它足以支持220扩展决策，但不等于最终220场五级稳定性论文主张。

### M4：220场内部候选物化

定义：扩展源候选220场物化、可确定性重建、全量机器门通过，形成供全量人工QA的内部候选；最终发布manifest尚未冻结。

### M5：人工、治理与最终版本冻结

定义：pilot全双标、全量人工核验与分层双标完成；所有修复经全量重建；专家仲裁、许可、泄漏检查和环境复现通过；最终数据哈希、manifest和拆分冻结。

### M6：论文级发布候选

只有同时满足以下条件才能使用这一称谓：

- 数据、协议、运行和报告四版本轴可追溯；
- 完整R26.18 Sentinel5有效；
- 两个强模型家族完成冻结Pilot20并通过220扩展前门；
- 主指标、曲线和置信区间按合同报告；
- 最终220场候选物化并通过全量门；
- 人工双标、专家仲裁与来源许可完成；

## 附录B：建议的授权文本最小要素

授权必须同时写明：

- 唯一`authorization_id`；
- 授权主体、授权来源任务/对话；
- 授权时间、时区和截止时间；
- 数据版本；
- 协议版本；
- 模型和provider；
- 精确run/cohort ID；
- 场次/题目；
- 零缓存保守估算上限、用户实际预算和各自的执行/人工监督方式；
- 是否允许重试；
- 硬失败停止规则；
- 输出目录必须全新；
- provider执行授权必须是一次性，并且只绑定一个精确run/cohort ID；
- 失效条件和撤销条件；
- 生命周期状态：`unused / consumed / revoked / expired`；
- 是否授权后续阶段。

如果没有写明后续阶段，默认不授权。无论运行完成、失败还是provider无响应，本次外部执行尝试后授权都应标记为`consumed`，不能在下一次运行或新对话中复用。若未来批准一个多运行计划，只能把它作为父级预算/范围批准；每个不同run ID仍须生成独立的一次性子授权和独立消费记录，同一run ID不得重复请求。

## 附录C：计划维护规则

- 每个里程碑后更新计划状态，但不删除历史决策；
- 新发现只能新增或版本化修订，不能静默改写已发生事实；
- 阈值变化必须在看新模型结果之前冻结；
- 每次修订附变更原因、影响范围和批准人；
- 当前版本的所有百分比目标均来自冻结合同，不代表已经实现。
