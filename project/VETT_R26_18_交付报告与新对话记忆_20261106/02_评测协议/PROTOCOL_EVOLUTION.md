# 评测协议演进：R26.16 → R26.18

## R26.16：未知证据引用的正确归因

旧规范把任何不存在的证据ID视为整批协议失败。这会让同批其他完整题目的事实与
证据结果全部消失。R26.16冻结`semantic_false_positive_v2`：

- 形状合法但不属于当前文档的`s_<24hex>`保留原样；
- 它在span和edge评分中作为假阳性；
- 只击穿受影响问题的完整证据链；
- 畸形ID、外来query/decision节点、缺题、截断和非法JSON仍是硬失败。

引用稳定性审计覆盖28,574个公开span、1,528个金标引用span和550,080个单字符
替换，没有发现碰撞。该层解决的是归因，不是放宽证据真实性。

## R26.17：题目覆盖的结构保证

`request_bound_v2`使用固定长度数组与题目ID枚举，但JSON Schema无法表达“每个ID
恰好出现一次”。GLM曾返回同一合法ID五次，造成其余四题缺失。

R26.17引入`exact_target_map_v3`：

- `decision_predictions`改为对象；
- 五个精确题目ID成为五个必需属性；
- 禁止额外键；
- 属性值不再冗余输出`question_id`；
- 本地规范化仍保留二次校验。

单场`match_0220`外测成功返回5/5题、无截断、无验证错误，证明题目覆盖失败模式
已经被provider侧实测消除。

## R26.18：集合语义与输出服从性分轨

新的五场尝试在`match_0021`返回了全部五题，但两个答案重复完全相同的证据边。
Schema已经声明`uniqueItems=true`，提示也禁止重复，但provider没有可靠执行。

将整批丢弃会损失有效能力测量，静默去重又会掩盖服从性失败。R26.18因此冻结
`canonical_set_v2`双轨协议：

### 语义轨

- `evidence_spans`按精确ID集合计分；
- `evidence_edges`按精确三元组集合计分；
- 完全相同成员只保留首次出现；
- 重复副本不获得额外信用；
- 未知但形状合法的引用仍保留为假阳性。

### 服从性轨

- 任一重复使对应题目标记为nonconformant；
- 报告题级服从率、受影响题数、重复组、冗余副本和最大重复次数；
- 新增“证据链+服从性”和“事实+证据链+服从性”联合精确指标。

### 仍然硬失败

- 非法或截断JSON；
- 缺题、多题、冲突题目身份；
- 缺少必需字段或字段类型错误；
- 非法归一化值、非法关系；
- 畸形ID或外来query/decision节点；
- 原始数组超过上限；
- provider/传输错误。

数组上限在去重前检查，模型不能用重复项绕过48边限制。

## 历史兼容

- 旧运行默认`strict_unique_v1`；重复仍是`INVALID_OUTPUT`。
- 新协议只允许和`edge_derived_v3 + exact_target_map_v3 + semantic_false_positive_v2`
  组合。
- 合同版本为`R26-C3-EDGE-9-CANONICAL-SET-CONFORMANCE`。
- 历史R26.17结果不追溯转正，后验回放只用于验证本地归因。
- 新旧协议不能合并成一个正式Sentinel5。
