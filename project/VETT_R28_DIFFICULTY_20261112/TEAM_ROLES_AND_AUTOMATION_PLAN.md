# VETT-Cricket R28 多智能体协作与自动化执行计划

**版本** R28.0（2026-11-12）
**配套** `PROPOSAL_VETT_R28_DIFFICULTY_AND_INTERPRETABILITY.md`（研究计划书）
**团队** `vett-r27-opt`（沿用，不新建；8 成员 / 22 任务）
**原则** 零付费推理 API · 本地优先 · 可重放 · 有界自治

## 1. 分工的第一原则：谁都不许自己给自己判分

这个项目过去最大的失败不是"数据不够难"，而是**测量与实现由同一批人（同一个模型）完成**，导致分数漂亮但不可解释。所以 R28 的角色划分只围绕一条铁律：

> **做数据的、跑模型的、判分的、发布的，四者分离。**

具体落地为四条隔离：

| 隔离 | 规则 |
|---|---|
| 实现 / 验证隔离 | `data_engineer` 写的生成器，`verifier` 独立复跑，不得共用同一验证脚本 |
| 标注 / 判分隔离 | `local_operator` 与 `annotator_alpha` 只产出标注，`judge_architect` 与机械真值判分 |
| 设计 / 测量隔离 | `data_designer` 定合同，`measurement_auditor` 独立复核合同是否被偷改 |
| 本地 / 云端双标尺 | 本地模型是**劳动力**，云端是**深度**，solver 是**唯一正确性锚点** |

## 2. 八个角色

| # | 角色 | 一句话职责 | 推理档 | 拥有任务 |
|---|---|---|---|---|
| 1 | **measurement_auditor** | 测量与统计的唯一权威，不下场做数据 | max | t2 t3 t19 t11 |
| 2 | **data_designer** | 冻结合同与预注册，写"什么算通过" | max | t4 **t22** |
| 3 | **data_engineer** | 生成器与构建，只管产出不管评价 | max | t5 t6 t7 |
| 4 | **verifier** | 独立验证、学术包、论文骨架 | max | t8 t9 **t23 t24** |
| 5 | **judge_architect** | 评测协议、双标尺仲裁、J 门 | high | t12 t17 |
| 6 | **pipeline_engineer** | 闭环流水线、自动化、预算熔断 | high | t1 t13 t20 |
| 7 | **annotator_alpha** | 云端深度标注（抽样，不追全量） | high | t16 |
| 8 | **local_operator** | 本地 7B 的唯一操作者与能力守门人 | max | t18 t14 t21 |

**为什么是 8 个而不是更少：** 上面四条隔离要求"实现者 ≠ 验证者"、"标注者 ≠ 判分者"、"设计者 ≠ 复核者"，最少需要 6 个独立身份；再加本地操作与云端标注两个独立执行体，正好 8。合并任何一个都会破坏隔离，进而重演"自己判自己"的老问题。

**为什么不是更多：** 每加一个成员就多一份上下文同步成本与 token 成本。22 个任务 / 8 个角色已经是 ~2.75 任务/人的密度，再加人会出现闲置。

## 4. 本地模型路由卡（基于实测，不是猜）

### 4.1 实测能力（Qwen2.5-7B-Instruct Q4_K_M，RTX 3070 8GB，100% GPU）

| 维度 | 实测值 | 结论 |
|---|---|---|
| JSON 服从率 | 30/30 | 短输入结构化输出可靠 |
| 短提示耗时 | 2.3 s | 适合大批量 |
| 8K 输入耗时 | 8.0 s | 可接受 |
| 80K 输入耗时 | 17.7 s 且无增益 | 禁止 |
| 生成速度 | 65–77 tok/s | 够用 |
| 40K 下信息字段准确率 | 4.20/9（先验 4.77/9） | **不能做求解** |
| 置信度输出 | 均值 60.53（应 0–1） | **不可用** |

### 4.2 ALLOW / DENY 白名单

| 任务 | 本地 | 输入上限 | 量 | 谁校验 |
|---|---|---:|---:|---|
| T1 因子/剂量可见性判断 | ✅ ALLOW | 3K tok | 160 | 机械真值 |
| T2 自然度 1–5 | ✅ ALLOW | 2K tok | 160 | 重测一致性 |
| span 主题标签 | ✅ ALLOW（条件） | 1K/条 | ~1000 | 机械真值 |
| 证书逐句一致性 | ✅ ALLOW | 2K tok | 160 | 云端核验 |
| 可读性评分 | ❌ DENY（0.667，ρ=−0.167，无区分度）| — | 0 | 回退机械 FRE 分档 |
| T3 提报裁定 | ❌ DENY | — | — | 云端 |
| 12 字段记录推导 | ❌ DENY | — | — | — |
| 置信度 / 仲裁 / 统计 | ❌ DENY | — | — | — |
| 任何 >8K tok 输入 | ❌ DENY | — | — | — |

**能力矩阵是上岗前置**：t18 先在 ≥30 个样本/任务上测一致率，低于 **0.85** 一律 DENY。t17 J 门若发现白名单任务不达标，流水线**自动降级**回云端缓存并写 `DEGRADED` 事件——不是人工发现，是代码判定。

### 4.3 为什么这样分配"不重也不轻"

- **不重**：本地只做"看一眼就能判断"的封闭式任务，单次 2–3 秒、输入 ≤3K token。凡是需要多步推导、需要算数、需要给概率的，一概不给。
- **不轻**：本地承担 **320 题 × ALLOW 任务 ≈ 1280+ 次调用**，是流水线里调用量最大的执行体。云端只做 52 次抽样（工作量比 123:1）。它拿到的是"量"，不是"难"。
- **可退化**：任一任务不达标即自动退出，不会拖垮流水线；退出后结果标 `DEGRADED`，报告里如实呈现覆盖率。

### 4.4 可重放要求

每次本地调用必须落盘：`input_sha256`、`prompt_template_version`、`temperature=0`、`seed`、`model_tag`、`raw_output`、`parsed_output`、`wall_clock`。**没有这些字段的输出不进统计。**

## 5. 自动化：一条命令从备份跑到报告

### 5.1 形态

```
python -m vett_r28.pipeline --config r28.toml --stage all
```

- `--stage`：可单独跑某阶段（`backup|measure|contract|build|twin|pipeline|matrix|annotate|judge|experiment|loopcheck|verify|release|report`）
- `--dry-run`：用合成输入跑通全链路，不写真实产物
- `--resume`：从上次中断点继续（按内容寻址缓存判定）
- 幂等：同输入同参数重跑不产生新结果，只命中缓存

### 5.2 五个内建机制

| 机制 | 实现 |
|---|---|
| **内容寻址缓存** | 键 = `sha256(input + params + prompt_version + model_tag)`；命中直接复用，杜绝重复付费/重复推理 |
| **门注册表** | 每个门是一个返回 `{verdict, evidence}` 的纯函数；PASS 才放行，FAIL 落 `gate_ledger.jsonl` |
| **有界修复循环** | 单门最多 2 轮修复；第 3 轮仍 FAIL → 升级为 `ESCALATED` 并停下等人工，不无限重试 |
| **自动降级** | 组件不可用（云端/本地/磁盘）→ 走预定义降级路径，写 `DEGRADED` 事件，流水线继续 |
| **预算熔断** | 每次调用记 token 到 `cost_ledger.jsonl`；超硬顶 → 立即 `BUDGET_STOP` 并落盘，不静默续跑 |

### 5.3 无人值守边界

**自治的（无需人工）：** 备份、测量复核、生成、构建、本地标注、云端抽样、评分、门判定、报告生成。
**不自治的（必须人工）：** 首次批准执行、预注册合同冻结后的任何端点修改、`ESCALATED` 事件处置、发布决定、任何触碰 R26.15 字节的操作。

这条边界写死在代码里：涉及上述动作的函数在 `allow_human_gate=True` 之外一律抛异常。

### 5.4 流水线可靠性的验收（t20）

| 演练 | 期望 |
|---|---|
| 杀进程后 `--resume` | 从断点继续，无重复扣费，产物一致 |
| 把本地服务停掉 | 自动降级，标 `DEGRADED`，链路不中断 |
| 篡改一个缓存文件 | 缓存校验失败 → 重算，不静默使用 |
| 同一命令跑两次 | 第二次全部命中缓存，产物哈希相同 |
| `--dry-run` | 全绿，不写真实目录 |
| 字节级重放 | 从发布包重算出报告里每个数字 |

## 6. 成本模型与熔断

| 项 | 计费 | 预算 |
|---|---|---:|
| 付费推理 API（主实验） | ¥0 | 硬顶 ¥0 |
| 云端抽样标注 | 按 token | 软顶 ¥3 |
| 本地推理 | ¥0 | 不限次数，限时长 |
| agent token（22 任务） | 按 token | 软顶 ¥70 |
| **总硬顶** | — | **¥100** |

**四条省钱规则（都在代码里）：**

1. **本地优先断言**：ALLOW 任务若检测到走了云端，直接报错——防止"顺手用贵的"。
2. **抽样而非全量**：云端只标 80 个分层样本，其余靠本地 + 机械真值。
3. **缓存即省钱**：同一输入永不重算。
4. **早停**：任一出口门 FAIL，后续阶段不启动（"A 不过 B 无意义"）。

## 8. 失败、回滚与停止

| 情形 | 动作 |
|---|---|
| 任一阶段异常退出 | 保留现场，`--resume` 可续；不删中间产物 |
| 门 FAIL 且修复 2 轮无效 | `ESCALATED`，停下等人，不自动改设计 |
| 预算触顶 | `BUDGET_STOP`，落盘，停止 |
| 发现 R26.15 被改动 | **立即停止全部工作**，用 t1 备份回滚，报告事故 |
| 实验显示未变难 | 按预注册如实报告，不换指标 |
| 用户要求终止 | 中断成员，保留产物，交付当前快照 |

**回滚脚本**随 t1 一起交付（`_BACKUPS\VETT_R28_PRE_CHANGE_20261112\restore.ps1`，支持 `-DryRun` 与 `-Scope all|frozen|code`）：一条命令把 R26.15 恢复到冻结状态，并验证 165 文件 / 93,346,177 字节 / 逐文件 sha256 / 可复现聚合 `343afde4…51bd` 一致。

**零漂移门的权威口径**：一律用 `PROTECTED_PATHS.json`（338 文件，逐文件 sha256 + 可复现聚合），不要用 `code\` 快照做权威——`code\` 是点时刻快照，其它进程仍在写 `analysis/` 与 `eval_runs/`。
