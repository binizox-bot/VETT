# VETT-Cricket R16–R26.18：长文本、整表、证据链与板球规则推理数据集

本仓库把板球记分根数据转换为受控的半合成长文本、整表恢复和证据链任务。当前数据静态候选仍是 **R26.15 content-dependency candidate v3**：20场、100题、25个情景家族；R26.16–R26.18是其本地评测协议加固层，不创建或暗改新的数据候选。R26.15已完成不物化全量数据的220场流式静态预检，并在R26.14答案盲化基础上新增反事实事实到受影响规则的内容依赖边。R26.16分离未知证据语义假阳性，R26.17固定题目键覆盖，R26.18再把证据集合语义与重复输出服从性分轨报告。R26.13和R24继续作为已披露捷径的失败对照。

## 当前结论

- 220/220 个 R20 实例通过机器发布门槛，其中 217 场为独立根，3 场为精确重复一致性控制。
- 根修复保留 98,447 个源单元格；91,555 个可靠单元格计分，6,892 个冲突相关单元格保留但不计分。
- 公开集含 9,260 篇文档、274,250 条真假混合声明和约 471.5 万词；单场 10,040–33,731 词。
- 首提、末提、多数值和最短修订链启发式分别为 36.48%、36.59%、43.74% 和 0%。
- R22保留91,555个整表目标，并新增5,500个“等级×任务族”证据探针；220/220场通过机器审计。
- 每个R22探针都必须不低于其对应R21目标的跨度数、关系边数和链深；全量完成54,516次决定性跨度/边删除检查。
- R22公开文本约700.2万词，高于对应R21生成基线约621.1万词，没有以缩短旧任务换取新增探针。
- L4/L5显式要求撤回旧分支、验证独立替换并做全局一致性合成，五类关系机制都出现在新增探针中。
- GLM-5.3-Flash在20场R22 pilot的500个证据探针上取得57.2% FAM和13.2% ASP；整体难度达标，但L2到L3出现-4个百分点倒置，因此五级校准尚未通过。

- R24独立磁盘审计、Oracle全指标及84项全仓回归测试通过；这不等同于强模型难度目标已经达成。
- R24失败审计复现了恒定反事实100%、旧角色词分类F1 100%、语义化选项标签100%，并记录于 `docs/R24_FAILURE_AUDIT.md`。
- R25.2从未改动的R22构建，保留7,944个表格目标和500个证据probe；新增100个状态求解决策题、1,308个原子证据span，替换R22 span为0。

## 数据使用边界

模型求解时只能读取对应版本的 `public/`。`private/` 含金标及证据图，`audit/` 含审计结果；两者必须与求解上下文物理隔离。不得把整个发布目录直接交给待测模型。

每个发布目录包含：

- `public/<match_id>/public_instance.json`：公开多文档输入和空目标结构；
- `private/<match_id>/private_gold.json`：目标值和来源坐标；
- `private/<match_id>/private_evidence.json`：声明、跨度哈希、图边和决定性支持；
- `audit/<match_id>.audit.json`：实例级门槛、反事实和消融结果；
- `MANIFEST.json`：发布文件的字节数和 SHA-256；
- `RELEASE_SUMMARY.json`、`RELEASE_REPORT.md`、`DATASET_CARD.md`：发布级结果与限制。

## 快速复核 R20

在仓库根目录运行：

```powershell
$env:PYTHONPATH = 'src'
python -m unittest discover -s tests -p 'test_*.py' -v
python -m vett_r20.cli audit-repair --release repair_r20
python -m vett_r20.cli audit-release --release dataset_r20_220
```

从已修复规范根重建完整数据集到一个空目录：

```powershell
$env:PYTHONPATH = 'src'
$roots = 'repair_r20\canonical_roots_220_repaired.jsonl'
python -m vett_r20.cli generate --roots $roots --output rebuild_r20 --seed 20027
python -m vett_r20.cli audit-release --release rebuild_r20
```

R20 构建器拒绝写入非空输出目录，以降低覆盖历史产物的风险。

## 可复现性与声明边界

生成过程仅依赖 Python 标准库、固定种子与规范根 JSONL。发布清单校验文件集合、字节数和 SHA-256；语义审计重新加载公开、金标和证据文件后独立求解。材料是由真实记分数据派生的受控半合成环境，不应被描述为原始逐球实况，也不应把机器门槛的 PASS 表述为人工真实性或通用模型不可解证明。
