# R26.13 测量有效性与 220 场扩展预检

> **追溯更正（2026-10-20）**：R26.13不再处于可付费哨兵状态。新增答案先验审计发现，不读取任何dossier文档的题面1NN可取得91.0%的12字段准确率、88.0%的信息字段准确率和72.0%的整记录精确率；其静态准入已改为`STATIC_ADMISSION_FAIL`。本文其余部分保留为当时设计记录，替代候选及修复证据见[R26.14答案盲化静态候选](R26_14_ANSWER_BLIND_STATIC_CANDIDATE.md)。

## 结论先行

R26.13原有结构与证明门通过，但答案先验门失败，因此不得进行付费经验哨兵，也不能宣称难度达标或发布220场。强模型事实宏准确率不高于65%、相邻等级至少相差8个百分点仍是待检验假设。

本版不是继续堆文本长度，而是修复一个会损害论文结论的测量漏洞：R26.12 的公开 span ID 含有 `fact`、`rule`、`shadow`、`authority` 等角色形态。完全不读文本的留一比赛分类器即可取得 1.000 macro-F1。这意味着模型即使返回了正确证据 ID，也可能只是利用元数据，而非构造证据链。R26.13 将所有公开 span ID 确定性映射为同形的 `s_<24 hex>`，映射只保存在私有证据文件；同一分类器降至 0.324176 macro-F1，即只会预测高度不平衡的多数类。

## 为什么这样设计

长上下文长度本身不是可靠难度。Lost in the Middle 表明证据位置会显著影响表现；RULER、HELMET、LongBench v2 和 NoLiMa 都说明，宣称“支持长上下文”并不等于能稳定完成跨位置检索、非字面匹配和多步推理。因此 R26.13 把 uniform 设为唯一正式输入，并生成 head、middle、tail 三个内容相同的位置诊断形式；位置形式移动的是正证据与必须排除证据的并集，避免只移动正证据造成混杂。

多跳题也不天然等于多跳推理。MuSiQue 和《Compositional Questions Do Not Necessitate Multi-hop Reasoning》提示，需要控制可分解捷径和单跳替代路径。因此每题现在接受三类更强的证明：

1. 仅用最小采信事实重建事实答案和单事实反事实答案；
2. 删除登记证据图的任一类型边，至少一个明确证明义务必须失效；
3. 每个登记事实或规则依赖在合法证据注册表中只能有一个候选证明。

这里严格区分“因果必要”和“合同内结构必要”。事实 span 的必要性由可复算 countermodel 证明；规则、身份和权限 span 的必要性只是在已声明证据图合同下成立，不冒充现实世界中绝对唯一的自然语言证明。这个边界与 ERASER 强调的充分性/完整性诊断一致，也避免把人工登记图误写成唯一哲学解释。

## 已落地的构造合同

- 公开 ID：全体同形、不可含角色词；私有映射可逆，并验证确定性 round-trip。
- 证据证明：事实充分性、事实 countermodel、单边删除、登记候选唯一性全部成为构建硬门禁。
- 捷径基线：span ID、document ID、文档类型和文档内位置均做 leave-one-match-out 角色分类。
- 位置诊断：uniform/head/middle/tail 共享相同 span ID 和文本，只改变证明 span 的位置。
- `proof_only` 诊断：只保留五题正证据与排除证据的无标签并集，用于分离“找证据失败”和“拿到证据仍不会合成”；不能与正式 uniform 分数混算。
- 运行协议：runner 明确记录 `public_input_form`，历史依赖 ID 前缀的消融在角色中立版本上 fail closed。
- provider schema：正式JSON Schema同时接受旧版ID与R26.13角色中立ID；真实provider路径与Oracle路径使用同一组ID约束测试。
- 执行授权：五场配置默认`execution_authorized=false`；未显式授权时，在读取环境密钥和创建provider请求之前终止。
- 语言表面：检测来源名词碰撞、缺失引号、内部ID、重复词、同姓实体标签和非规则文本重复；不允许通过放宽正则掩盖生成根缺陷。
- 准入门：静态通过只允许下一步五场 uniform 哨兵，不允许直接物化或发布 220 场。

- 100/100 题最小事实可重建事实与反事实记录；

- 100/100 题登记最小证明唯一；
- 28,574 个公开 span 的 ID 角色分类 macro-F1 从 R26.12 的 1.000 降为 0.324176；
- 字面 query top-k 对 L3/L4/L5 的证据召回为 16.85%/20.16%/16.42%；
- Oracle 的事实、状态、正证据、排除证据、类型边及事实+完整证据链均为 100%，证明评分闭环自洽。Oracle 各级都为 100%，所以它不用于检验相邻难度差。
- 相同基础发布与 seed=26041 在独立临时目录重建，165个文件全部字节一致，manifest SHA-256 均为 `9290f5ea6e68b0cb3f1cb0ba543e8dc235204ca42e76cb2a36d4a30b9920bc12`。
- 自动语言表面审计覆盖1,528个本版生成span和100道题，已知退化、缺失句末标点、引号不平衡、非规则文本重复均为0。五场×五级的25题私有样本经助手逐项复核后无阻断缺陷；这不是独立人工标注。

220 场流式预检：

- 220/220 R25 基础实例、220/220 R26.13 实例、1,100/1,100 题通过；
- 326,308 个公开 span ID，跨场碰撞 0；
- 25 个场景家族各出现 44 次，五级各 220 题；
- 平均结构负载 L1–L5 为 0.334911、0.472576、0.578324、0.756609、0.882623；

- 已知语言表面退化为0；此前全量门捕获的两处`lower lower-desk`由生成根修复后消失，审计规则保持不变；
- 外部 provider 请求为 0，未物化完整 220 场候选。

## 五场请求就绪状态

- 冻结场次为`match_0021/0066/0067/0162/0220`，每场一个请求，避免单次失败污染其他场次；
- 输入形式仅为正式`uniform`，输出使用request-bound typed-edge协议和严格JSON Schema；
- 保守估算总费用0.9399元，合同上限1.20元；最大上下文占用上界24.956%，配置输出上限16,384 token，最小Oracle输出余量1.315倍；
- 6类协议错误、3类语义错误、2类传输/包络错误的故障注入均能正确归因；
- `proof_only`、middle、head/tail均不是默认连跑项目，而是由冻结阈值按诊断价值逐级触发，防止重复花费；
- 当前配置没有执行授权，provider请求数为0。以上成本是本地保守估计，不是账单。

## 不能声称的内容

静态结构负载递增不等于模型准确率递减。当前不能声称：强模型事实宏准确率已经低于 65%、任意相邻级已经达到 8 个百分点、proof-only 一定显著优于 uniform、位置偏差已经存在，或 220 场已经获得发布授权。

R26.13 改变了公开 ID，旧 R26.12 的模型响应不得复用；否则模型返回的 ID 与新输入不一致，也会污染协议归因。

## 最省钱且有决策价值的下一步

1. 只用一个经济但有足够指令能力的模型跑预注册五场 uniform；任何超时、截断或 JSON 协议失败先修 runner，不计入语义难度。
2. 只有 uniform 协议有效后，才在同五场跑 proof-only。若提升明显，说明主要瓶颈是长上下文证据识别；提升不明显则是规则合成/证据图构造。
3. 只有识别差距足够大且论文需要位置结论时，再跑 middle；head/tail 延后到确实需要估计位置范围时。
4. 五场结果满足继续价值后，才跑 20 场、两个强模型家族；通过冻结的 65% 与 8 个百分点门槛后，才能批准物化 220 场。
