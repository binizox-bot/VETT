# R26.9 证据角色协议失败的修正

## 结论

Gate3 暴露了两个不同问题，必须分开处理：

1. 模型把其他事件的拒绝证据绑定到当前问题，这是需要被基准计分的语义错误。
2. 旧协议要求模型把同一拒绝证据同时写入 `rejected_evidence_spans` 和 `rejects` 边；两处不一致会让整批失去计分资格，这是评测协议的冗余表示问题。

不能修改私有金标准、不能替模型补边，也不能简单忽略一致性错误。正确修正是消除冗余表示，同时完整保留语义惩罚。

## v3 单一事实来源

`edge_derived_v3` 不再要求模型输出 `rejected_evidence_spans`。模型只输出类型化证据图，评测器把所有 `relation == "rejects"` 边的 `target_id` 集合确定性地派生为拒绝证据集合，再交给原有评分器。

因此：

- 正确的 `rejects` 边同时产生正确的拒绝集合与类型边得分。
- 错误目标仍会降低拒绝证据 F1 和类型边 F1。
- 漏掉 `rejects` 边会派生出空集合，相关语义分数为零或下降。
- 评测器不会查询私有金标准来补答案。
- 只有缺目标、未知节点、非法关系、重复边、截断或解析损坏等真正的协议错误才阻止正式计分。

这不是放宽任务，而是把“模型没找到证据”从传输失败恢复为可测量的模型能力错误。

## 对真实 Gate3 错误的本地重放

真实失败片段已固化为 `tests/fixtures/r26_gate3_cross_incident_binding_failure.json`。在旧 v2 下，拒绝数组与边不一致，批次无效。在 v3 下，同一输出会从实际边派生出空拒绝集合；它可以进入评分，但私有正确拒绝 span 不会被插入，因此错误没有被隐藏。

把完整五题旧回执离线送入 v3 归一化器时，协议错误为 0；该重放仅验证计分行为，不追溯转为正式结果。所得事实字段准确率为 81.67%，整记录准确率为 20%，正证据 span F1 为 41.79%，拒绝证据 F1 为 25%，类型边 F1 为 33.66%，证据链联合全对率和事实—证据联合全对率均为 0。这说明 v3 没有美化模型表现：它保留了跨事件绑定、漏证据与漏边造成的全部语义惩罚。
