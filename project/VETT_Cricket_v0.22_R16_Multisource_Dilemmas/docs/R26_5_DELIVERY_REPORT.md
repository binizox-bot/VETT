# R26.5 交付与晋级报告

## 结论

R26.5 已完成20场pilot的证据角色修复、严格输出协议、静态审计、快捷方式审计、Oracle闭环、指标区分性变异测试和全仓回归。它解决的是R26.4证据评分中的定义歧义，不是一次未经验证的“继续加难”。当前仍不批准扩展到220场：外部免费模型被账户级余额网关拦截，尚无R26.5经验校准结果。

## 为什么需要R26.5

R26.4两场有效GLM结果中，模型有37个正证据span假阳性，其中11个其实是金标图中`rejects`边必须指向的同事件冲突。模型识别这些冲突是构造证据链的必要动作，但旧契约又把它们按普通正证据假阳性处罚，导致span指标和图指标语义不一致。

R26.5只拆分证据角色：

- `evidence_spans`：身份、权限、被采信事实和适用规则等决定性正证据；
- `rejected_evidence_spans`：必须显式驳回、并由`rejects`边指向的同事件冲突；
- `evidence_edges`：七类有向关系；
- 完整链exact：上述三部分必须同时精确匹配。

两类span必须互斥，排除证据集合必须与`rejects`边目标精确一致。协议版本为`R26-C3-EDGE-3-ROLE-SPLIT`。

## 无回归边界

## 指标区分性

在同一份Oracle预测上分别施加一个单点错误：

- 把一条排除证据误塞入正证据：只有正span指标下降；
- 漏掉一条排除证据：只有排除span指标下降；
- 改错一条边的关系类型：只有edge指标下降。

三种情况下，其他两个子指标保持100%，完整链exact均由100%降为99%。这证明三个子指标测量的错误类型不同，而不是重复命名同一个集合。

## 免费模型与停止条件

已读取SiliconFlow当前模型目录，并只尝试官方标为免费的`XingChenAGI/Xing4.0-29B`与`Qwen/Qwen3.5-4B`。两次请求都在生成前被HTTP 402“账户余额不足”拦截，输入/输出token和费用均为0。错误分析现将其标为`ACCOUNT_BALANCE`、语义覆盖率0%，不会把它记成模型答错。

在余额状态改变前继续请求只会产生重复失败，因此已停止外部调用。下一步有效门槛仍是：使用新run ID完成五场、协议有效的免费或低成本哨兵，验证强模型事实宏准确率、五级相邻差、正/排除证据和边指标后，再决定是否修改文本或扩到220场。
