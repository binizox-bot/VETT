# R26.12 评测流程与难度稳定性优化报告

## 1. 当前结论

R26.12 的 **20 场候选版结构门禁通过**，可以作为后续 220 场受控生成的设计依据；但它还没有完成强模型经验校准，也没有生成新的 220 场 R26 数据，因此不能宣称“五级难度已被模型验证”或“论文数据集已完成”。

机器可读的最终状态见 `analysis/r26_12_admission/R26_12_ADMISSION_REPORT.json`：

- 结构扩展准入：`PASS`
- 220 场语义基座输入就绪：`BLOCKED`（20/220，缺 200 场）
- Sentinel5：`1/5`，`INCOMPLETE_SENTINEL5`
- 强模型五级区分已证明：否
- 220 场 R26 数据已生成：否
- 论文发布就绪：否

这一区分是刻意的。静态审计、oracle 满分和结构指数只能证明数据及工具闭环，不能替代真实强模型结果。

## 2. 本轮修复的评测流程

### 2.1 冻结指标和严格阶段规模

主难度指标继续使用冻结的 `decision_field_level_macro_accuracy`。强模型目标宏平均区间为 0.45–0.65，相邻等级目标下降至少 0.08。阶段规模固定为：

- `single_protocol_gate`：1 场，只验证协议；
- `sentinel5`：恰好 5 场，只作筛查；
- `pilot20`：恰好 20 场，采用 10,000 次按比赛区组配对 bootstrap；
- 未声明阶段、场数不符、截断、JSON 修补或目标缺失一律不能产生正式难度结论。

实现位置：`src/vett_eval/metric_contract.py`、`src/vett_eval/runner.py`、`src/vett_eval/panel.py`。

### 2.2 请求级输出约束

`request_bound_v2 + edge_derived_v3` 将返回结果绑定到请求哈希和精确问题 ID 集合，不再要求模型重复顶层 `instance_id`，并由 `rejects` 边推导被拒证据集合。这减少重复输出和协议性浪费，但不降低事实、反事实或证据图任务本身。

当前四场待运行配置还包含：

- 每场单独一批，避免跨场超长输出；
- `max_tokens=14336`，估计输出余量比 1.246826；
- 超时 2400 秒；
- `max_retries=0`，避免失败后自动重复扣费；
- checkpoint、断点续跑和重复请求阻止；
- 任何单批失败即停止；失败与语义错误分开报告。

配置文件：`eval_configs/r26_12_glm53_request_bound_sentinel5_collection4.json`。

### 2.3 增量 cohort 和请求等价证明

历史结果不能仅因为模型名、参数和比赛 ID 相同就复用。cohort 现在会：

1. 从 checkpoint 读取历史请求哈希；
2. 用历史 release 重构原请求并核对哈希，检测评测代码漂移；
3. 用候选 release 构造请求，去除纯路径字段后比较完整语义请求哈希；
4. 只有两步都通过，历史输出才能给候选版计分。

结果：

- `match_0067`：历史请求可重构，候选语义请求完全一致，可安全复用；
- 更早的 `match_0066`：历史请求无法用当前代码严格重构，虽然内容看似相同，仍被排除；
- 因此正确的 Sentinel5 组成是复用 0067，再新增 0021、0066、0162、0220 四场。

这避免了为了省钱而污染实验，也避免把已经安全可复用的 0067 重复付费。

实现和产物：`src/vett_eval/cohort.py`、`design/r26_12_glm53_sentinel5_cohort.json`、`analysis/r26_12_glm53_sentinel5_cohort/COHORT_INDEX.json`。

### 2.4 结构化错误分析

`src/vett_r26/error_analysis.py` 将错误拆分为事实字段、状态、不变量、正证据、拒绝证据、缺边/多边、身份链、权威链、决策证明、跨事件绑定和误抄其他事件。只有完整 Sentinel5 或 Pilot20 才允许据此触发数据修改；单场历史结果只能诊断，不能改难度。

## 3. 难度设计的实质升级

### 3.1 五个跨等级能力锚点

原设计的 25 个场景族各只属于一个等级，容易把“板球题型差异”误认为“等级差异”。R26.12 将它们组织为五个跨 L1–L5 的能力锚点：

- 投球判罚优先级与附加分；
- 无效投球下的出局资格；
- 边界与计分账本归属；
- 事件顺序与终止状态；
- 出局、申诉与控制性观察。

锚点是私有实验设计字段，不进入模型输入。它允许比较“同一板球能力在五级负担下”的变化，同时保留自然场景的多样性。

### 3.2 从真实公开证据派生难度轴

旧结构度量把部分 R25 模板标志当成 R26 的真实负担。候选版改为从最终文本和证明图派生：

- 权威决策来自实际 `authorizes/rejects` 边；
- 顺序深度来自实际板球事件顺序规则，以及公开文本中的最高修订号或最后锁定前记录；
- 证据量、文档覆盖、边数和离散度来自最终放置后的文档；
- 绑定、规则交互、反事实传播仍分别计量，避免用一个“长度分数”定义难度。

修正前漏记来源版本/锁时顺序，造成 L3→L4 有 20% 的伪负跃迁。修正后：

| 相邻等级 | 平均结构增量 | 负跃迁占比 |
|---|---:|---:|
| L1→L2 | 0.136257 | 0.00 |
| L2→L3 | 0.106225 | 0.00 |
| L3→L4 | 0.179667 | 0.00 |
| L4→L5 | 0.123277 | 0.00 |

五个锚点的所有相邻结构增量均为正，最小值为 0.040168；100 题中结构向量唯一率为 0.72，最大重复数为 4。结构合同也被收紧为：负跃迁占比最多 0.10、同锚点相邻平均增量至少 0.035。

必须注意：结构增量不是准确率百分点，不能用 0.040168 推断模型会下降 4 个百分点。

### 3.3 预注册的后续调整规则

在完整 Sentinel5 之前，已经冻结四个相邻等级各自允许的候选机制：L2 双键权威选择、L3 同规则跨事件绑定碰撞、L4 修订号与锁时复合顺序、L5 上游单事实干预后的多账本传播。每项必须同时改变至少两个结构轴，最多增加两个决定性证据 span，并保留 R22/R25 语义和单一原子反事实。仅加长文本、增加无关噪声、答案文风提示和单场触发均被禁止。

注册表及审计：`design/r26_12_preregistered_adjustment_registry.json`、`analysis/r26_12_admission/ADJUSTMENT_REGISTRY_AUDIT.json`。

### 3.4 220 场均衡分配

私有扩展分配器采用带种子的五阶分组拉丁方。220 场分为 44 个五场区组；每个区组内，每个等级都覆盖五个能力锚点一次，每场也覆盖五个锚点一次。最终：

- 220 场；
- 1100 个决策题位；
- 44 个区组；
- 25 个“锚点×等级”组合各 44 次；
- 25 个场景族各 44 次；
- 分配账本为私有信息，不暴露给模型。

实现和产物：`src/vett_r26/expansion_design.py`、`analysis/r26_12_expansion_plan_220/PRIVATE_EXPANSION_ALLOCATION.json`。

这只是生成分配计划。输入覆盖预检显示 R25 语义基座目前只有 20/220 场同时具备 public、private gold 和 private evidence，缺 200 场；`partial_generation_permitted=false`。生成器现已支持由私有分配表显式指定每个等级的场景族，并通过一场 R22→R25→R26 端到端内存构建与两级实例审计，默认 pilot 生成行为保持不变。完整 220 场仍必须先构造并审计全部 R25 语义基座，再逐场执行 R26 渲染、金标重构、捷径审计和清单哈希。预检产物为 `analysis/r26_12_expansion_plan_220/EXPANSION_INPUT_COVERAGE.json`。
