# R26.15 内容依赖证据链静态候选

## 结论

R26.15 是 R26.14 的窄幅、仅证据图扩展。当前交付候选为
`r26_15_content_dependency_candidate_v3/`，静态准入状态为
`STATIC_CAUSAL_MEASUREMENT_PASS_EMPIRICAL_BLOCKED`。候选数据版本和 manifest
没有变化；新增的是更严格的审计与评分协议，而不是未经证据支持的 R26.16 数据改写。

它没有增加文本长度，没有改题面、事实、状态、反事实、正证据或排除证据，也没有删除或改写原有 2,492 条边。新增的 `conditions_rule` 关系要求模型把“反事实中被改动的事实 span”连接到“所有依赖该事实的适用规则 span”。这使完整证据链不能再只凭节点角色套固定拓扑。

静态通过不等于强模型难度达标。强模型事实宏平均不高于 65%、相邻等级至少 8 个百分点、多模型家族稳健性和独立人工自然度仍须通过外部哨兵验证。本轮没有请求任何 provider。

## 为什么需要 R26.15

对 R26.14 做预注册式结构捷径审计后发现：若已经知道每个节点的私有角色和正/排除成员关系，不读取金标边也能用固定模板恢复全部 2,492 条边，边 F1 和整图精确率都是 100%。这不表示公开文本泄漏了节点角色，但说明“边 F1”把大量机械连边与真正的内容依赖混在一起，可能高估证据链构造能力。

同一轮审计也确认：

- 问题到全部正证据的 BM25 `recall@gold-k` 为 22.56%；移除反事实标记和语义入口 span 后，剩余证据召回仅 7.28%。
- 问题表面 1NN 对类型关系计数签名的精确率为 6%，对总边数的精确率为 8%。
- 公开数值/长度/位置特征预测五级难度的 macro-F1 为 25.27%。

因此真实缺陷不是“答案可从题面直接读出”，而是“找到角色后，旧图的拓扑过于机械”。

## 唯一、经济的新增关系

冻结合同是 `design/r26_15_content_dependency_contract.json`。最终规则为：

1. 唯一源节点是该题 `counterfactual.changed_field` 对应的决定性事实 span。
2. 遍历该题实际适用的规则。
3. 若冻结依赖注册表声明该规则依赖这个改动字段，则加入一条 `事实 span -> conditions_rule -> 规则 span`。
4. 不给不依赖该字段的规则添加回退边。

早期中间候选没有被直接交付：

- “每条规则固定选一个事实”虽然能增加 600 条边，但对未受反事实影响的规则需要私有优先级打破多个合法事实之间的平局，金标不够唯一。
- “加入所有事实—规则依赖”在 100 题中有 40 题超过 48 边输出上限，最大达到 59 条，增加费用和截断风险。
- 最终的“反事实事实—受影响规则全集”没有私有回退平局，20 场只新增 324 条边，每题 1–7 条，总图最多 38 条。

这次收敛优先保证答案可靠性和输出经济性，而不是单纯堆边制造难度。

角色模板 F1 仍然较高是预期现象：它完整保留所有继承边，只缺少内容依赖边。因此不能只报告总体边 F1。R26.15 同时报告 `content_dependency` 关系组 F1、端点恢复率、在已恢复端点上的条件连边 F1，以及事实+完整证据链联合精确率。

单边删除变异确认：删除一条 `conditions_rule` 后，事实答案和金标端点恢复率仍为 100%，但内容依赖组 F1、条件连边 F1和事实+完整链 exact 都会下降。这证明新增指标测的是连边语义，而不是重复奖励事实答案。

## 独立实现的因果一致性审计

原发布审计与候选生成器共用同一个边推导函数，所以它能证明构建一致，却不能单独证明语义登记没有自我重复。为此新增了不导入候选边生成器或原发布审计器的第二套实现，依据冻结的输入依赖和输出责任表，从 `private_gold`、原始 `r25_evidence_claims` 及公开 span 重新构造期望边。

每条边必须同时满足：源是唯一的反事实改动事实 span；目标是唯一的适用规则 span；改动字段属于该规则输入；事实与反事实之间至少一个由该规则负责的决策字段实际变化；两个端点均为公开且在场内唯一的 span。20 场 324/324 条、100/100 题及全部 25 个场景族通过；220 场流式复核为 3,564/3,564 条、1,100/1,100 题通过。

这是一项事后、独立实现的内部一致性审计，不是独立人工双标。它也不声称某一条规则是孤立且唯一的结构因果父节点，因为多个板球法则可能共同约束同一个输出。

## 指标掩盖与机会量修复

冻结变异测试揭示了可复现的测量缺陷：删除全部 324 条 `conditions_rule` 后，总体 typed-edge micro-F1 仍为 93.896%，但内容依赖 F1、内容问题宏 F1、字段宏 F1、场景宏 F1和事实+完整链 exact 均为 0。因此论文和模型报告必须同时给出：

- 内容依赖边 P/R/F1 与问题宏 F1；
- 干预字段等权宏 F1和场景族等权宏 F1；
- 各等级金标边机会量；
- 端点恢复率、条件连边 F1与事实+完整链 exact。

内容边平均机会量在 L1–L5 为 3.8 / 4.8 / 3.4 / 2.6 / 1.6，最大/最小为 3 倍。在相同单边正确率下，边较少的等级天然更容易整题全对；例如假设每条边独立有 70% 正确率，预期内容整题 exact 为 28.62% / 21.96% / 38.31% / 43.82% / 58.66%。因此 `content_dependency_edge_exact_by_level` 只能用于诊断，不能单独证明五级难度排序。

五种变异均已闭环：全部删除、全部反向、全部改错关系、单边删除和单条伪边添加。它们分别击穿召回、方向/关系、严格链或精度，而事实分数保持不变。冻结的 R26.9 事实主指标和 45–65% 目标没有被事后改写；内容图指标测量的是额外能力。

新增代码与历史生成、runner、评分和发布审计一起完成全仓 186 项回归，全部通过；本轮 provider 请求数为 0。

## 运行协议与版本隔离

统一 runner 的 JSON Schema 可以表达 `conditions_rule`，但实际请求和响应规范化按每道题的 `r26_public_contract.evidence_edge_relations` 限制关系集合：

- R26.15 请求会公开新增关系定义，并允许 `conditions_rule`。
- R26.14 及更早版本的请求 schema 不包含该关系，规范化也会拒绝它。

这避免新协议悄悄放宽历史版本，使旧实验仍可复现。
