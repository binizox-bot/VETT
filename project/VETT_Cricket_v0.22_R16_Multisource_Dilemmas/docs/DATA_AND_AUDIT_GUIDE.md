# 数据结构与自动审计指南

## 1. 数据层级

完整交付包含四类材料：

1. 220 场原始文本/记分表数据及其工作副本；
2. 2026-09-03 全量研究归档，含历史工程、结果、清单和复核材料；
3. 当前 R16–R19 生成与审计工程；
4. R16–R19 已生成发布数据。

R16–R19 都从只读规范根数据生成。生成后的 `release*` 目录不是上游真值，不得反向作为下一版本的金标来源。

## 2. 单实例契约

`public_instance.json` 是唯一允许交给求解模型的文件，主要包含：

- 多来源文档、可见文档标识、发布时间和正文；
- 待填的目标结构与任务说明；
- 求解所需的自然语言修订、撤回、血缘和范围证据。

`private_gold.json` 保存答案、目标类型和规范来源坐标。`private_evidence.json` 保存结构化声明、公开跨度定位及哈希、状态转换、依赖、修订/撤回/转载边和最小决定性支持集。`audit.json` 保存实例级机器检查、弱基线、删除反事实与图边消融。

## 3. 证据链审计标准

一个直接目标只有同时满足下列条件才可发布：

1. 作用域与 match、innings、field 精确匹配；
2. 每条用于求解的结构化声明都能定位到公开正文中的原始跨度；
3. 公开跨度的哈希与私有记录一致，且声明值可从该跨度恢复；
4. 修订、撤回、无效化和转载关系有肯定式公开语言见证；
5. 否定、引用或仅提到关系词的文本不能被当作有效图边；
6. 执行全部状态转换后只剩一个可接受值，否则失败关闭；
7. 删除决定性公开跨度后，答案必须改变或变为不可解析；
8. 删除任一标记为必要的图边后，至少一个目标必须错误或歧义；
9. 公开层不得泄漏私有字段、金标、结构化图边或角色化文档 ID；
10. 相关局分、附加分和派生字段必须满足板球算术约束。

## 4. 发布级自动门槛

R19 还要求：

- 6/6 实例级审计全部 PASS；
- 每实例 14 个直接目标分别落在 14 篇决定性文档中；
- 任一文档承载的直接答案不超过 10%；
- 首次提及、末次数组提及、最新时间戳、多数表决及全部已登记公开捷径不超过 10%；
- 固定修订序位 1–16、全局最新修订和逐目标最新修订均不超过 10%；
- 标识符归一化后的跨实例文本开头多样性通过门槛；
- 发布目录文件集合、字节数和 SHA-256 与 `MANIFEST.json` 完全一致。

## 5. 无人工参与的复核流程

```powershell
$env:PYTHONPATH = 'src'
python -m unittest discover -s tests -p 'test_*.py' -v
python -m vett_r16.cli audit --release release
python -m vett_r17.cli audit --release release_r17
python -m vett_r18.cli audit --release release_r18
python -m vett_r19.cli audit --release release_r19
```

命令退出码为 0 且 JSON 中 `status`、`manifest_status` 均为 `PASS`，才表示该版本通过当前机器标准。若移动完整交付包，先切换到工程目录再运行；无需网络或外部模型 API。

## 6. 盲测协议

进行模型能力测试时，应由评测程序只复制 `public/` 中的实例到隔离目录。预测提交后，再由另一个进程加载 `private_gold.json` 评分。模型上下文、检索索引、日志和工具路径均不得接触 `private/`、`audit/`、`MANIFEST.json`、发布报告或本指南中的答案统计。

建议把模型版本、推理参数、提示词哈希、输入文件 SHA-256、预测原文、解析结果和评分器版本全部写入一次性运行清单，以便以后重放。

## 7. 已知限制

- 当前只有 6 场试点，不代表全部 220 场或 217 个规范根的分布。
- 未执行外部盲测模型运行，因此不能声称“现有大模型无法分辨”。
- 未执行人工自然度审计；文本多样性和语法检查只是机械代理指标。
- 数据是受控半合成材料，不是原始逐球解说的逐字存档。
- 公开已知捷径为零不等于不存在未知捷径；新增攻击器后必须重新审计。

## 8. 引用结果时的最低要求

任何报告至少应写明数据版本、种子、实例数、直接/派生目标数、模型可见范围、审计命令、清单哈希状态以及是否进行了盲测或人工审计。不得只引用 `PASS` 而省略版本和边界。
