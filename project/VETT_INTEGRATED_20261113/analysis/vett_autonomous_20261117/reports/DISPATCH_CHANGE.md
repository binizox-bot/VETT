# 派发顺序改动（模型分组）

## 改动

- 旧：ORDER BY batch_id, rowid（同批内按创建顺序，模型频繁切换）
- 新：ORDER BY batch_id, model, rowid（同批内同模型连续，再切下一个模型）
- 未改提示、模板、上下文、输出预算、解码配置或任务键；只改领取顺序。

## 证据

旧全库平均 load_ms = 11,993.7（3,502 结果）。新段（15:42:34 后）前 29 条：

- gemma 14 条：2 次大加载，12 次 <100 ms，平均 load 2,028 ms
- llama 14 条：2 次大加载，12 次 <100 ms，平均 load 2,451 ms
- qwen 1 条：首次加载 15,167 ms

连续序列示例：gemma 4.9/12.1/5.4/5.0/4.7/4.7/5.4/5.3 ms，随后 llama 17,175.2 ms，再 5.3/5.8/5.2/5.4/6.0/6.7/5.2 ms。即每个模型每批只付一次加载，块内几乎为 0。

## 结论

- 模型加载从“每任务一次”降为“每批每模型一次”。
- 早期新段吞吐约 29 条/2.5 分钟（约 700 条/小时），高于旧段 240–260 条/小时；样本小，继续观察。
- 每批仍覆盖三个模型；单 worker、一次一个请求不变。
- keep_alive 未改，仍单模型驻留，避免多模型压满 8GB 显存。

## 回滚

- worker.py 中 ORDER BY batch_id, model, rowid 改回 ORDER BY batch_id, rowid 并重启 supervisor 即可。
