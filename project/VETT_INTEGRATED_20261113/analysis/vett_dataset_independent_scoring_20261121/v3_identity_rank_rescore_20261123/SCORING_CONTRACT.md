# VETT 离线评分契约 v3

版本：`score-v3-identity-rank-recovery-20261123`

## 冻结边界

- 本版本只读 `B228`–`B235`、`B247` 的整表 manifest/原始 JSONL，以及 `B243`–`B246` 的最小诊断 manifest/原始 JSONL。
- 不修改 `v1_frozen`、运行中 SQLite、worker 或队列。35 个输入文件的绝对路径、字节数和 SHA-256 见 `SOURCE_INVENTORY.csv`；再次运行时任一哈希变化都会终止。
- 旧内嵌分数原样保留在原 JSONL，并逐行带入 `old_embedded_*` 列；新分数只写入本目录。

## 六个独立评分面

1. **严格格式**：唯一合法根结构为 `{"fields": {...}}`；根层不得有额外键，字段值必须是标量，重复键直接不通过。
2. **可恢复内容**：依次尝试严格 JSON、围栏 JSON、最后以与金标无关的词法规则提取所有“字符串键: 标量值”。恢复器不知道合法键名和金标值。
3. **冻结字段分**：只对当前 manifest 的字段逐格比较，报告正确、错误、缺失、未定；这是旧分→新分的可比轴。
4. **人物身份数值分**：先用姓名把模型行映射到实际球员，再比较该人的 wickets/runs；绝不把第 2 行的数值自动归给金标第 2 人。
5. **成员集合分**：独立判断两名球员是否构成通知后的合法 top-2。
6. **行序分**：仅在成员集合可判时，按 wickets 降序、runs 升序判断顺序；与成员集合分开报告。全队 wickets 另列，不随局部归属变更。

## 重复、冲突与未定

- 同一键重复且规范化值相同：标为 `duplicate_same`，严格格式为 0，可恢复内容仍可比较。
- 同一键出现冲突值：该字段标为 `conflict`，可恢复内容记 `undetermined`，不借助金标选择一个值。
- 姓名缺失、重复身份或字段无法唯一归属：相关身份/数值面保持未定；不会按行号补配。
- 精确同分发生在 top-2 截止线时，不使用源表稳定顺序制造唯一答案。任何合法同分候选集合均可接受；集合之外的人仍明确判错。若入选两人本身完全同分，行序保持未定。
