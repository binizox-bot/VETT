## 2. 为什么 V1.0 走不下去（四个结构性缺陷，全部可算术验证）

### 2.1 它的门在数学上不可达

V1.0 的 Pilot20 门要求：四个相邻点估计都至少下降 8pp，且至少 3 个相邻差的 95% 置信下界 > 0。Pilot20 每级 20 题。

- p=0.6、n=5/级：SE = **21.9pp**
- p=0.6、n=20/级：SE = **11.0pp**，两个独立比例之差的 SE = **15.5pp**
- 要在 0.60 vs 0.52 上做出 8pp 显著差（α=.05, power=.8）：**每级 604 题**；配对相关 0.5 时 **302 题**；配对相关 0.8 时约 **121 题**；仅让 95% CI 半宽 ≤8pp 也要 **148 题/级**

**Pilot20 差 6–30 倍（取决于配对相关）。** 这不是"再跑一次就能过"，是设计上永远过不了。项目已经为此消耗了 R26.16–R26.18 三轮、近 1.6 元和一整周，本质是在给一个不可辨识的量做重复测量。

### 2.2 主指标测的不主要是阅读

- 12 字段里 3 个常零 → 25 题 × 3 = 75 个格子是"白送分"。主指标仍按 12 字段平均，等于把 25% 的权重给了不需要读文档的字段。
- 剩下 9 个信息字段：55.11% vs 常数先验 52.89%。
- 也就是说：**常数预测器（每个字段永远输出该字段最常见值）在同一批 25 题 × 12 字段上能得 64.67%，模型 66.33%，增量 1.67pp**，远小于一个标准误。

一个主指标与常数预测器的差距小于 1 个标准误的基准，不能作为"模型能力"证据发表，也不能用来决定数据要不要加难。

### 2.3 协议混淆吃掉了难度信号

同一批 25 题上：字段 66.3%、span 45.2%、edge 29.9%、内容边 9.2%、完整链 0%。

模型能定位证据（45%），但构造不出类型化边（30%），更构造不出内容依赖边（9%）。这 30pp 的落差里，有多少是"不懂因果"，有多少是"JSON 里边的三元组写不对"？当前设计分不开。R26.18 的 `canonical_set_v2` 虽然把重复从"整批报废"降级为"服从性告警"，但**边的序列化负担仍然计入语义分**。

### 2.4 证据等级不够发表

- 1 个模型家族、1 个 provider、1 套提示；
- 没有弱模型/中等模型基线，无法证明"区分能力"；
- 金标从未人工核验（只有机器自洽）；
- n=25，任何排名或等级结论都在噪声内；
- 没有 LICENSE、没有匹配的数据卡、没有 held-out 提交协议。

**结论：V1.0 的下一阶段（Pilot20，估算 5.6 元）会得到 20 个"每级 20 题"的不可辨识估计，然后继续卡在同一道门上。** 这是可以事先预测的浪费，所以我不重复它。

## 3. V2.0 的三个根本改变

### 3.1 因变量：从"难度"改成"证据敏感性"

不再问"模型答对多少"，改问"**模型的答案跟不跟证据走**"。

对同一道题构造孪生卷宗：

- **V+（决定性事实被改）**：答案**必须**变。变 = 模型真的读了那条 span。
- **V−（干扰 span 被改）**：答案**必须不变**。变 = 模型被表面相似性带偏。
- **V0（只改文档顺序/措辞）**：答案**必须不变**。变 = 模型依赖位置或文体。

三个指标：`flip⁺`、`stability⁻`、`stability⁰`。这是**题内配对**设计，同一个模型、同一道题、只差一个事实，方差被消掉一大半。n=50 就能检测 20pp 级别的偏差，而 n=20 的等级比例检测不了 8pp。

这也是唯一能把"这数据集到底测什么"讲清楚的实验。

### 3.2 统计：从"等级比例"改成"项目特征模型"

R26.15 的每题金标里已经有 20+ 维 `difficulty_vector`：`authority_decisions`、`binding_collision_count`、`counterfactual_blast_radius`、`derivation_depth`、`operator_interaction_count`、`evidence_span_count`、`temporal_depth`、`hard_negative_similarity`、`context_band`……

现在这些特征只用来"描述难度"，没进入统计。把它们当自变量、把每题对错当因变量，拟合 `logit P(correct) = f(features)`（或 2PL IRT），收益是：

- 25 个观测变成 25 × 20 个特征观测，**参数可估**；
- "哪一类机制导致失败"变成可检验的系数，而不是靠 5 个等级的平均值猜；
- 可以**预注册预测**下一批题哪些会错，再用实测验证（这是很强的论文素材）；
- 等级退化为描述性标签，不再承担统计推断。

**这是一个可以立刻做、零成本、且比 V1.0 更有信息量的动作。**

### 3.3 成本：从"单 provider 付费"改成"本地面板 + API 锚点"

本机有 RTX 3070 8GB。125K token 的批次装不下，但**逐题输入**（单题约 30–40K token，Q4 量化 + 32K 上下文）可以跑。

`vett_eval.runner` 已经支持 `adapter: "command"`（`runner.py:2156` 的 `adapter_fn` 字典里有 `"command": _command_response`），只是从来没有配置用过。接 Ollama / llama.cpp 是**配置工作，不是开发工作**。

产出：模型家族 1 → 4，弱/中/强基线阶梯一次到位，API 成本 0。

## 4. 数据层升级（仍然不碰 R26.15 的字节）

### 4.1 用因子设计替代序数五级

五级 L1–L5 是人工调的序数刻度：既不可辨识（见 §2.1），也无法归因（L2 为什么难？不知道）。改成 **2×2×2×2 因子**：

| 因子 | 水平 | 含义 |
| --- | --- | --- |
| A 权威 | A0 单一权威 / A1 冲突来源需裁决 | 是否需要来源优先级 |
| B 时间 | B0 无修订 / B1 修订链 ≥2 | 是否需要沿时间推理 |
| C 推导 | C0 直接取值 / C1 需计算 | 是否需要执行规则 |
| D 范围 | D0 单文档 / D1 跨文档 | 是否需要绑定多篇 |

16 个格子，每格 4 题 = 64 题/模型。收益：主效应和交互**可识别**，能回答"是权威冲突还是跨文档绑定让模型失败"，而这是 V1.0 永远回答不了的。

**零成本路径**：先用现有 100 题的 `difficulty_vector` 把每题重新标到 4 个二元因子上，直接拟合——不生成新数据。只有当因子模型证明某个因子真的重要时，才做真正的因子平衡生成（R27）。

### 4.2 配对孪生题（服务 §3.1）

为每题生成 V+/V−/V0 三个孪生卷宗。数据量 ×4，但这是**唯一能产生因果对比**的增量。优先做 50 题 × 3 变体 = 150 份输入。

### 4.3 把常数字段变成非常数

`ledger.BYE`、`ledger.LEG_BYE`、`ledger.PENALTY` 在现有题里几乎恒为零。两个选择：

- **(a) 便宜的**：评分时直接剔除，主指标只用 9 个信息字段（评测框架已经算了，只是没当主指标）；
- **(b) 正确的**：在生成器里增加 byes/leg-byes/penalty 非零的场景，让它们成为真实变量。

(b) 是数据升级，(a) 是测量修复。先做 (a)，(b) 进 R27 需求池。

### 4.4 加"弃权"通道

模型现在给 0.93 的置信度然后答错（Brier 0.627，比常数 0.5 的 0.25 还差）。这说明置信度携带的是**负信息**。

在输出契约里加 `abstain: true` 选项，评分改成 **risk–coverage 曲线**：允许模型在没把握时弃权，报"覆盖率 80% 时的准确率"。这比单点 Brier 更能反映真实部署价值，也更容易被审稿人接受。

### 4.5 给边的输出降噪

edge F1 29.9% 而 span F1 45.2%。建议允许两种等价提交格式（三元组数组 / 邻接表 / 边列表），归一化后评分；或提供受约束解码的 grammar。**把"会不会写 JSON"从"会不会推理"里剥出来**，否则永远说不清边任务的低分是什么。

### 4.6 建一个"人审 verified split"

从 100 题里分层抽 100（或 50）题，两人独立标注 + 仲裁，冻结成 `verified_split`。这是唯一能让审稿人相信金标的办法，也是所有指标的最终校验集。

### 4.7 检索-推理分离的输入阶梯

现在一次请求约 125K token（5 题共享整份卷宗）。审稿人一定会问：失败是因为长上下文检索，还是因为规则推理？现有 `proof_only` 只覆盖了终点，缺中间档。

补三档输入消融（不改数据，只改喂给模型的子集）：

| 档 | 输入 | 若准确率大幅上升说明 |
| --- | --- | --- |
| F 全卷宗 | 现状 | — |
| D 只给决定性文档 | 去掉无关文档，保留所有 span | 失败在**检索** |
| P 只给决定性 span（已有 `proof_only`） | 只剩最小证据集 | 失败在**证据选择** |
| S 只给规则 + 事实表 | 无叙事文本 | 失败在**语言理解** |

这是**零成本、当天可做**的消融，能一次性回答"瓶颈在哪一层"，比再加 100 道题有用得多。

### 4.8 外部效度：考虑用真实比赛数据接地

现有 220 场是半合成的（虚构球场与球员）。审稿人一定会问"为什么不用真实板球数据"。公开的逐球数据（如 Cricsheet，需自行核对许可）可以提供真实分布，把生成器锚在真实比赛上，哪怕只做 20 场对照。这是**提升外部效度最便宜的一步**，V1.0 完全没有考虑。

## 5. 测量层：新指标体系

### 5.1 双主指标

1. **`informative_field_skill`**（逐级报告）：`(acc − prior) / (1 − prior)`，prior 必须**逐级重算**。
2. **`evidence_sensitivity`**：`flip⁺`、`stability⁻`、`stability⁰`（见 §6）。

原 `decision_field_level_macro_accuracy` 保留为描述性指标，不再单独作为决策依据。

### 5.2 必报的分解指标

`span_recall` / `span_precision` / `edge_construction_given_spans` / `content_edge_exact` / `serialization_failure_rate` / `paired_cf_exact`。

其中 `edge_construction_given_spans` 已经在现有分析里（`conditional_edge_link_f1 = 0.7696`）——**这是全项目最有价值的一个数**：给定正确的节点，边连对的比例是 77%，说明模型的边推理其实不差，差的是节点恢复（span F1 45%）。**当前报告把这个数埋在 70 KB 的 JSON 里，主报告只写 edge F1 29.9%，严重低估了模型能力，也误判了瓶颈。**

### 5.3 服从性与弃权作为独立轴

conformance、abstention、provider availability 三者都单独报，不进主分。

### 5.4 先修三个测量 bug

1. 逐级先验没算 → 无法判断"L2–L5 低于先验"是真结论还是聚合假象；
2. Brier 的标度与计算单位未核 → 0.627 可能是标度错，不一定是过度自信；
3. `observed_informative_field_value_cells: 41` 的含义不明 → 需确认分母。

## 6. 科学层：证据敏感性实验（V2.0 的核心）

### 设计

- 样本：现有 100 题中分层抽 50 题（每级 10 题，覆盖 25 个情景族）。
- 每题生成 3 个孪生卷宗：V+（改一条决定性 span 的取值，金标答案随之改变）、V−（改一条干扰 span）、V0（文档顺序置换）。
- 每个模型跑 50×4 = 200 次请求（原题 + 3 变体），逐题输入。

### 指标

| 指标 | 定义 | 合格线（预注册） |
| --- | --- | --- |
| `flip⁺` | V+ 下答案变成"新金标"的比例 | ≥ 2× 随机基线 |
| `stability⁻` | V− 下答案不变的比例 | ≥ 80% |
| `stability⁰` | V0 下答案不变的比例 | ≥ 90% |
| `blind_flip` | V+ 下答案变了但没变成新金标 | 越低越好（= 蒙对） |

### 为什么这值得做

- 它是**题内因果**，不是相关性；n=50 有功效。
- 它能直接回答"模型是在读文档还是在猜"——这是本数据集唯一不可替代的科学问题。
- 它把"难度"从目标降级为副产品：一个模型可以很难，但如果它对 V+ 不敏感，那它失败的原因就不是"证据推理"。
- 成本：本地模型 0 元；API 锚点约 ¥1–2。

## 11. 复检：对我自己方案的七个反驳

1. **"换主指标是不是事后挑指标？"**
   是风险。对策：V2 指标在**任何新运行之前**冻结进 `design/`，并同时报告旧指标；用"为什么旧指标不合格"的算术（§2.2）作为换指标的**事前**理由，而不是看结果后挑好看的。

2. **"本地 7B 太弱，代表不了强模型。"**
   对。它是**基线阶梯**，不是替代品。API 锚点（GLM）保留。而且弱模型本来就该有——没有弱模型，就无法证明基准有区分度。

3. **"逐题输入改了协议，不可比。"**
   对。所以它是**独立 arm**，同评分、不合并、单独报告。这与现有 `proof_only` / 位置变体的处理方式一致。

4. **"证据敏感性会不会被先验猜中？"**
   会。对策：V+ 的新值不选最常见值，选第二常见值；并加 V0 作对照；`blind_flip` 单独报告，把"蒙对"和"读对"分开。

5. **"人工审计太慢，拖垮进度。"**
   25 题试标可在 2 天内完成，用一致率估计正式样本量。若两人一致率已 ≥98%，100 题约 2 人日/人。

6. **"废掉 8pp 门是不是降低标准？"**
   不是。是把**不可估的量**换成**可估的量**：从"每对等级差 8pp"改成"因子效应显著且跨模型稳定"。主张变弱了，但变成真的。

7. **"不物化 220 是不是浪费已有工作？"**
   生成器是确定性的，随时可重跑；等待的边际成本≈0，发一个测量不可信的 220 场的成本很高。

**我对自己方案的保留意见**：D 阶段的因果对比依赖"改一个事实只影响一个答案"这个前提。R26.15 的 `counterfactual_blast_radius` 显示一次干预平均改 5 个输出字段，所以 V+ 的"新金标"必须由求解器重算而不是人手改——这一步如果实现错，整个 D 阶段作废。这是最大的技术风险，必须先做 5 题的原型验证。

## 12. 学术承认评估（问题 2）

### 12.1 能站住的部分

1. **生成器的可验证性**：每题带最小充分证据集、countermodel（换掉事实必然改变输出）、删除测试。这比常见的"证据标注"强一个量级。
2. **四轨协议**：可用性 / 硬协议 / 服从性 / 语义分开，是对 LLM 评测卫生的真实方法贡献。
3. **失败档案**：R24 恒定反事实 100%、线索分类器 F1 100%、R26.13 题面 1NN 91%——这些负结果对社区有用，且很难得（多数论文不发表失败）。
4. **冲突掩码**：6,892 个单元格"保留但不猜"，是可复用的数据治理做法。

### 12.2 站不住的部分

1. **"强模型做不到"的难度主张**：n=25、单模型、主指标与常数先验差 2.2pp，**不可发表**。
2. **五级难度曲线**：L2→L3 倒置、每级 5 题，**不可发表**。
3. **"220 场基准"**：未物化、未人审、无 held-out 协议，**不可发表**。
4. **自然度**：纯合成文本，无人工自然度审计，审稿人一定会打。

### 12.4 定位

必须把卖点从"难"改成"**带因果证书的证据整合诊断仪**"。相关工作至少要覆盖：

- **Text-to-table**：[T3（EMNLP 2024）](https://aclanthology.org/2024.emnlp-main.523/) 是最接近的直系工作——T3 做的是"多文档 → 全局元组 → 一张表"的生成；R20 是"多文档修订链 + 冲突掩码 + 整表恢复"，R26 再叠加类型化最小证据图与反事实必要性。定位必须说清：**T3 测生成质量，R26 测证据使用**。
- **无参考表的可解释评测**：[TabReX（ACL 2026）](https://aclanthology.org/2026.acl-long.2176/)。
- **证据归因**：R4C（ACL 2020）、Shi et al.（TACL 2022）、partial-input 系列（Feng et al., ACL 2019）。
- **反事实知识图谱推理**：[Investigating Reasoning in LLMs with Counterfactual Knowledge Graphs](https://dl.acm.org/doi/10.1145/3770855.3817451)（2026）——这是 D 阶段最接近的工作，必须差异化。
- **规则推理**：RuleArena（2412.08972）、GSM-DC（2505.18761）。
- **长上下文**：RULER / ∞Bench / LongBench 系列——要说明"长度不是我们的变量，证据结构才是"。

### 12.5 合规：一个必须马上处理的问题

- `VETT_Cricket_.../tmp/pdfs/mcc_laws_2026.pdf`（983,617 B）与 `.txt`（232,613 B）是 **MCC 法则全文**，在交付包里。MCC 主张版权，**公开发布不能带这两个文件**。
- 公开文本里已有直接引用，例如 `"Law 22.9: after Wide, dismissal remains possible only under Hit wicket, Obstructing the field, Run out or Stumped."`——短引用可辩 fair use，但要在数据卡里写明来源与引用范围。
- 合成比赛文本本身可自主许可（建议数据 CC-BY-4.0、代码 MIT/Apache-2.0），但必须在数据卡声明"全部比赛与球员为合成"。

### 12.6 投稿路线

1. **先发 workshop / resource track**（LREC-COLING、ACL SRW 之外的 Resource & Evaluation、NeurIPS D&B）：卖点是仪器 + 失败档案 + 四轨协议。**不需要 220 场，不需要强模型结论。**
2. **主会**只在 E（人审）+ C（面板）+ D（敏感性）都过之后考虑，且主张限定为"20 场开发集上的诊断结果"。
3. 若坚持"220 场泛化难度"主张，还必须完成独立盲测（每级 ≥100 独立题、比赛分块 bootstrap），那是另一个量级的投入。

### 12.7 一句话结论

**作为"更难基准"——现在拿不到承认，而且再花 5.6 元也拿不到。**
**作为"可验证的证据整合诊断资源 + 评测方法学"——可以拿到承认，前提是 A、C、E、F 四件事做完；这四件事的总 API 预算是 0–2 元。**
